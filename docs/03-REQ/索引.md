## 7. 每个功能的内部结构模板

> 所有功能规格遵循统一结构，Read 时可按需跳转到子段落：

| 子段落 | 包含内容 |
|--------|---------|
| 功能描述 | 一句话概述 + 业务规则 |
| 前置条件 | 执行前的状态/权限/数据要求 |
| 输入参数 | 请求字段、类型、校验规则 |
| 处理流程 | 步骤编号的伪代码/流程 |
| 数据操作（SQL级） | INSERT/UPDATE/SELECT 的完整 SQL |
| 状态流转 | 本操作涉及的状态变更（旧→新） |
| 事务边界 | 事务范围说明（部分功能有） |
| 异常处理 | 错误场景 + 错误码映射 |
| 并发控制 | 锁策略 / 乐观锁 / 重试 |
| 权限控制 | 允许的角色 + 数据权限 |

## 8. AI 检索建议

**场景 1: "某功能的完整规格"**
→ 先在 §2 功能 ID 索引找到行号 → Read 该文件 offset=行号 limit=200

**场景 2: "某数据表结构"**
→ 先在 §3 数据表索引找到行号 → Read 该文件 offset=行号 limit=60

**场景 3: "某状态流转规则"**
→ 先在 §4 状态机索引找到具体模块 → Read 对应行号段

**场景 4: "某错误码的定义"**
→ 先在 §5 错误码索引找到码段 → Read 对应行号

**场景 5: "某概念涉及哪些模块"**
→ 在 §6 跨模块概念索引找到所有相关位置 → 按需 Read

**场景 6: "全局性规则（事务/并发/权限/时间）"**
→ 直接 Read REQ-全局.md 对应章节（§1 文件总览有行号）
