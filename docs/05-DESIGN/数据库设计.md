## 1. 数据库概述

| 项目 | 值 |
|------|---|
| 数据库类型 | MySQL 8.0 |
| 数据库名称 | `vaccine_db` |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB（默认） |
| 事务隔离级别 | `READ_COMMITTED` |
| 表数量 | 27 张 |

### 1.1 设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **无物理外键** | 所有 FK 关系在应用层通过 Repository 校验，不使用 `FOREIGN KEY` 约束 |
| 2 | **统一主键** | 全部使用 `BIGINT AUTO_INCREMENT` |
| 3 | **逻辑删除预留** | 全局配置 `deleted` 字段（当前未启用，预留扩展） |
| 4 | **时间戳标准化** | `create_time` 默认 `CURRENT_TIMESTAMP`，`update_time` 默认 `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |
| 5 | **乐观锁** | `hospital_vaccine_summary.version` 字段用于库存汇总并发控制 |

### 1.2 无物理外键策略

```
为什么不使用物理外键：
├── 避免级联锁：高并发场景下 FK 检查可能导致锁升级
├── 提升性能：INSERT/UPDATE 无需额外 FK 校验开销
├── 灵活的数据清理：可按业务规则清理数据，不受 FK 约束
└── 应用层保障：Repository 实现中通过查询校验数据一致性

一致性保障机制：
├── Repository 层校验：写入前查询关联数据是否存在
├── 业务规则校验：领域服务中的业务规则检查
├── 定时补偿任务：检测并修复不一致数据
└── 数据库索引：通过索引保证查询性能
```

**状态流转（status 字段）：**

```
1(APPOINTED) ──取消──▶ 3(CANCELLED)
1(APPOINTED) ──过期──▶ 4(EXPIRED)
1(APPOINTED) ──签到──▶ 6(SIGNED_IN)
6(SIGNED_IN) ──预检通过▶ 7(PRECHECK_PASS)
6(SIGNED_IN) ──预检失败▶ 9(PRECHECK_FAIL)
7(PRECHECK_PASS) ──登记──▶ 8(REGISTERED)
8(REGISTERED) ──接种──▶ 10(OBSERVING)
10(OBSERVING) ──留观结束▶ 2(COMPLETED)
```

**库存操作 SQL：**

```sql
-- 锁定库存（登记时调用，FOR UPDATE 防并发）
UPDATE hospital_vaccine_stock
SET locked_stock = locked_stock + 1
WHERE batch_id = #{batchId} AND locked_stock < available_stock;

-- 扣减库存（接种时调用）
UPDATE hospital_vaccine_stock
SET available_stock = available_stock - 1, locked_stock = locked_stock - 1
WHERE batch_id = #{batchId} AND available_stock >= 1 AND locked_stock >= 1;

-- 释放库存（取消预约时调用）
UPDATE hospital_vaccine_stock
SET locked_stock = locked_stock - 1
WHERE batch_id = #{batchId} AND locked_stock > 0;
```

## 5. 索引设计说明

### 5.1 核心查询索引

| 查询场景 | 使用的索引 | 说明 |
|---------|----------|------|
| 用户登录 | `uk_phone(phone)` | 手机号唯一索引，登录查询 |
| 用户预约列表 | `idx_user_id_status(user_id, status)` | 复合索引：按用户ID + 状态筛选，覆盖用户查看自己的预约列表 |
| 时段容量检查 | `idx_date_slot_status(vaccine_id, date, slot, status)` | 创建预约前检查时段是否已满 |
| FEFO 批次选取 | `idx_vaccine_id(vaccine_id)`, `idx_expiry_date(expiry_date)`, `idx_fefo_selection(hospital_id, available_stock, locked_stock)` | 复合查询：按疫苗ID筛选 + 有效期排序 + 库存过滤 |
| 今日签到列表 | `idx_appointment_date(appointment_date)`, `idx_status(status)` | 按日期 + 状态查询 |
| 库存锁定/扣减 | `uk_hospital_batch(hospital_id, batch_id)` | 唯一索引 + WHERE batch_id 条件 |
| 库存汇总乐观锁 | `uk_hospital_vaccine(hospital_id, vaccine_id)` | 唯一索引 + version 字段 |

### 5.2 序列号生成策略

| 序列号 | 格式 | 生成方式 | 示例 |
|-------|------|---------|------|
| 预约编号 | APT + YYYYMMDD + 4seq | `SELECT MAX(appointment_no)` 当日最大值 + 1 | APT202604030001 |
| 排队号 | A + 3seq | `SELECT MAX(queue_no)` 当日最大值 + 1 | A001 |
| 注射号 | INJ + YYYYMMDD + 4seq | `SELECT MAX(injection_id)` 当日最大值 + 1 | INJ202604030001 |
| 调拨单号 | TF + YYYYMMDD + 4seq | `SELECT MAX(transfer_no)` 当日最大值 + 1 | TF202604030001 |
| 销毁单号 | BD + YYYYMMDD + 4seq | `SELECT MAX(dispose_no)` 当日最大值 + 1 | BD202604030001 |

> 所有序列号生成在 Repository 层实现，使用数据库当日最大值 + 1 策略，配合 UNIQUE 约束防止重复。
