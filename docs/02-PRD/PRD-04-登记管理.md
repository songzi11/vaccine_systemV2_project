## 1. 模块概述

### 1.1 模块定位

登记批次模块包含两个子模块：

1. **登记子模块**：负责疫苗接种前的信息核实、批次分配和排队管理工作，是接种流程的第4个环节（预检→登记→接种）
2. **批次子模块**：负责疫苗批次的全生命周期管理，包括批次查询、批次分配（FEFO原则）、批次调拨、批次销毁、库存预警等

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 登记信息核实 | 预检评估（属于预检模块） |
| 批次分配（FEFO） | 疫苗接种执行（属于接种模块） |
| 排队号生成 | 留观管理（属于留观模块） |
| 库存锁定 | 疫苗目录管理（属于疫苗模块） |
| 批次查询、调拨、销毁 | 供应商接口（属于外部系统） |
| 库存预警通知 | 用户通知（属于通知模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| DOCTOR_REGISTER | 登记医生 | 查看待登记队列、核实信息、分配批次（FEFO）、排队管理（叫号/过号/确认到号） |
| DOCTOR_STOCK | 库存管理医生 | 批次查询、调拨、销毁、库存预警查看 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 查看批次统计、批次审核 |

### 1.4 核心业务价值

- **FEFO批次管理**：优先使用临期批次，降低疫苗过期浪费
- **流程衔接**：登记环节是预检和接种的桥梁，确保信息准确传递
- **库存实时锁定**：登记时锁定库存，接种时扣减，避免超卖
- **批次可追溯**：完整记录批次使用情况，支持质量问题追溯
- **库存预警**：自动监控库存状态，及时预警临期和低库存

### 1.5 业务场景

**场景1：家长完成预检后到登记窗口**
```
家长到登记窗口
  ↓
登记医生查询待登记队列
  ↓
找到对应预约
  ↓
核实儿童信息和预约信息
  ↓
系统FEFO分配批次（仅查status=0正常状态，优先快过期）
  ↓
  ├─ 有可用批次 → 系统锁定库存 → 生成排队号
  │               → 通知家长（APP推送：排队号、等候人数、接种窗口信息）
  │               → 家长前往接种窗口等待叫号
  │
  └─ 无可用批次 → 返回错误，建议家长重新预约
```

**场景2：库存管理医生调拨批次**
```
库存管理医生发起调拨
  ↓
选择调出位置和调入位置
  ↓
选择疫苗和批次
  ↓
输入调拨数量
  ↓
系统检查调出位置库存是否充足
  ↓
系统扣减调出位置库存
  ↓
系统增加调入位置库存
  ↓
记录调拨日志
```

### 2.2 功能详情

#### F-REGISTER-001: 查看待登记队列

**功能描述：** 登记医生查询预检通过但尚未登记的预约列表。

**输入参数：**
- 医生ID（从会话中获取）
- 预约日期（可选，默认当天）
- 筛选条件（可选）：全部/已登记/待登记

**输出结果：**
- 预约列表：
  - 预约ID
  - 预约号
  - 儿童姓名
  - 预检时间
  - 预检结果
  - 登记状态

**映射API：** GET /api/register/queue?date={date}&filter={filter}

**查询逻辑：**
```sql
SELECT a.id, a.appointment_no, cp.name AS child_name, pcr.created_at AS precheck_time, pcr.result
FROM appointment a
JOIN child_profile cp ON a.child_id = cp.id
JOIN pre_check_record pcr ON a.id = pcr.appointment_id
WHERE a.appointment_date = ?
  AND a.status = 7
ORDER BY pcr.created_at ASC;
```

> **排序规则：** 登记队列按预检通过时间升序排列（先通过先登记）。

#### F-REGISTER-004: FEFO分配批次

**功能描述：** 按照先过期先出（First Expired First Out）原则分配疫苗批次。

**输入参数：**
- 疫苗ID（必填）
- 医院ID（必填，固定为1）

**请求方式：** POST（含行级锁，有副作用，不适用GET）

**输出结果：**
- 批次ID
- 批次号
- 有效期
- 可用库存
- 锁定库存

**映射API：** POST /api/register/batch/assign

**分配规则（FEFO）：**
```sql
SELECT b.id, b.batch_no, b.expiry_date, s.available_stock
FROM vaccine_batch b
JOIN hospital_vaccine_stock s ON b.id = s.batch_id
WHERE b.vaccine_id = ?
  AND s.hospital_id = ?
  AND b.status = 0  -- 仅正常状态
  AND s.available_stock > 0
  AND b.expiry_date > NOW()
ORDER BY b.expiry_date ASC
LIMIT 1
FOR UPDATE;  -- 加锁防止并发
```

**规则说明：**
1. 批次状态必须为正常（status=0），不包含临期批次
2. 可用库存必须大于0（available_stock > 0）
3. 有效期必须大于当前时间
4. 按有效期升序排列，取第一个
5. 使用FOR UPDATE加锁，防止并发冲突
6. 若查询无结果：返回错误，建议家长重新预约，不继续登记

---

#### F-REGISTER-005: 锁定库存

**功能描述：** 登记时锁定批次库存，避免同一批次被重复分配。

**输入参数：**
- 批次ID（必填）
- 锁数量（必填，固定为1）

**输出结果：**
- 锁定成功：返回锁定后的库存信息
- 锁定失败：返回失败原因

**映射API：** POST /api/register/stock/lock

**锁定逻辑：**
```sql
-- 锁定库存（available不变，locked += 1）
UPDATE hospital_vaccine_stock
SET locked_stock = locked_stock + 1
WHERE batch_id = ? AND available_stock > 0;

-- 验证是否锁定成功
SELECT affected_rows();
```

**规则说明：**
1. 可用库存必须大于锁数量
2. locked_stock += 锁数量
3. available_stock不变
4. 接种时扣减时同时减去locked_stock

#### F-REGISTER-006: 生成排队号

**功能描述：** 生成唯一的排队号，用于登记窗口的排队管理。

**输入参数：**
- 预约日期（必填）
- 窗口功能类型（可选，默认为当前医生所在窗口功能类型）

**输出结果：**
- 排队号（格式：窗口功能前缀 + 3位序号，如A001、A002...）

**请求方式：** POST（生成排队号有副作用，创建排队记录，不适用GET）

**映射API：** POST /api/register/queue/no

**生成规则（SRD 4.5）：**
1. 排队号格式：窗口功能前缀 + 3位数字
2. 登记窗口前缀为"A"，如A001、A002
3. 每种窗口功能类型拥有独立队列
4. 当天排队号从001开始递增
5. 数字部分当天唯一，第二天重置为001
6. 使用数据库序列或原子计数器生成

**SQL示例：**
```sql
-- 获取当天该窗口功能类型的最大排队号
SELECT MAX(queue_number) AS max_queue_number
FROM register_queue
WHERE DATE(created_at) = ?;

-- 生成新排队号
new_queue_number = 'A' + LPAD(CAST(max_queue_number + 1 AS VARCHAR), 3, '0');
```

- 保存失败：返回失败原因

**映射API：** POST /api/register/save

**保存逻辑：**
```sql
-- 开启事务
BEGIN;

-- 保存登记记录
INSERT INTO register_queue (appointment_id, queue_number, queue_order, status, doctor_id, created_at)
VALUES (?, ?, ?, 0, ?, NOW());

-- 更新预约状态（SRD 5.2 node 4）
UPDATE appointment
SET status = 8,
    register_time = NOW(),
    current_window = 'REGISTER',
    batch_id = ?,
    queue_number = ?
WHERE id = ?;

-- 提交事务
COMMIT;
```

**通知规则（SRD 5.4）：**
登记完成后发送APP推送通知，包含：
- 排队号
- 当前等候人数
- 接种窗口信息

## 4. 用户操作流程

### 4.1 登记医生流程：执行登记

```
┌─────────────────────────────────────────────────────────────┐
│  步骤1：查看待登记队列                                    │
│  - 登记医生登录终端                                        │
│  - 进入待登记队列页面                                      │
│  - 系统显示当天待登记预约                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤2：查找预约                                          │
│  - 家长到登记窗口出示预检通过凭证                          │
│  - 登记医生输入预约号或儿童姓名搜索                        │
│  - 系统实时过滤预约列表                                    │
│  - 登记医生找到对应预约                                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤3：查看预约详情                                      │
│  - 登记医生点击"登记"按钮                                  │
│  - 系统跳转到登记页面                                      │
│  - 系统显示预约信息、儿童信息、疫苗信息、预检信息            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤4：核实信息                                          │
│  - 家长出示儿童接种卡和身份证                              │
│  - 登记医生核对预约信息与实物是否一致                      │
│  - 登记医生勾选"信息核实无误"                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤5：系统FEFO分配批次                                  │
│  - 系统自动调用FEFO分配批次接口                            │
│  - 系统按有效期升序查询可用批次（仅status=0正常状态）       │
│  - 系统选取有效期最早的批次                                │
│  - 若无可用批次：返回错误，建议家长重新预约                │
│  - 系统显示批次信息：                                      │
│    • 批次号                                                │
│    • 有效期                                                │
│    • 可用库存                                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤6：锁定库存                                          │
│  - 系统自动调用锁定库存接口                                │
│  - 系统锁定1支库存：                                        │
│    • available_stock不变                                    │
│    • locked_stock += 1                                      │
│  - 系统显示锁定的库存信息                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
```

## 5. 业务规则

### 5.1 登记业务规则

#### 规则1：预约状态校验
- 规则描述：只有状态为"预检通过"（status=7）的预约可以登记
- 执行逻辑：`appointment.status = 7`
- 失败提示返回：`该预约未通过预检，无法登记`

#### 规则2：预检结果校验
- 规则描述：预约的预检结果必须为通过（PASS）
- 执行逻辑：
  ```sql
  SELECT result FROM pre_check_record WHERE appointment_id = ?;
  ```
  结果必须为'PASS'
- 失败提示返回：`该预约预检未通过，无法登记`

#### 规则3：FEFO批次分配规则
- 规则描述：按有效期升序分配批次，优先使用有效期最早的批次（仅正常状态）
- 执行逻辑：
  ```sql
  SELECT b.id, b.batch_no, b.expiry_date, s.available_stock
  FROM vaccine_batch b
  JOIN hospital_vaccine_stock s ON b.id = s.batch_id
  WHERE b.vaccine_id = ?
    AND s.hospital_id = ?
    AND b.status = 0  -- 仅正常状态
    AND s.available_stock > 0
    AND b.expiry_date > NOW()
  ORDER BY b.expiry_date ASC
  LIMIT 1
  FOR UPDATE;  -- 加锁防止并发
  ```
- 若查询无结果：返回错误，建议家长重新预约，不继续登记

#### 规则3a：并发控制
- 规则描述：FEFO批次分配使用数据库行级锁防止并发分配同一批次
- 锁定方式：`SELECT ... FOR UPDATE` 行级锁
- 锁定范围：仅锁定被选中的批次记录，不影响其他批次的正常分配
- 锁定时机：事务开始时获取，事务提交/回滚时释放
- 并发冲突处理：获取锁失败时等待重试，最多等待3秒；超时后返回错误码4152

#### 规则3b：登记时库存不足处理
- 规则描述：当FEFO分配未找到可用批次（所有可用批次库存不足或全部过期）时的处理流程
- 触发条件：FEFO查询无结果（规则3返回空集）
- 处理流程：
  1. 向用户/医生提示"库存不足，无法完成登记"
  2. 预约状态保持为 7（预检通过），用户可重新排队等候
  3. 用户可选择：
     - a. 等待新批次入库后重新排队
     - b. 取消预约
     - c. 重新预约其他时段

#### 规则4：批次状态校验
- 规则描述：分配的批次状态必须为正常（status=0）
- 执行逻辑：`vaccine_batch.status = 0`
- 失败提示返回：`该批次状态异常，无法分配`

#### 规则5：批次可用库存校验
- 规则描述：分配的批次可用库存必须大于0
- 执行逻辑：`hospital_vaccine_stock.available_stock > 0`
- 失败提示返回：`该批次库存不足，无法分配`

#### 规则6：批次有效期校验
- 规则描述：分配的批次有效期必须大于当前时间
- 执行逻辑：`vaccine_batch.expiry_date > NOW()`
- 失败提示返回：`该批次已过期，无法分配`

#### 规则7：库存锁定规则
- 规则描述：登记时锁定1支库存，不减可用库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock + 1
  WHERE batch_id = ? AND available_stock > 0;
  ```
- 规则说明：
  - locked_stock += 1
  - available_stock不变
  - 接种时扣减时同时减去locked_stock

#### 规则8：排队号生成规则
- 规则描述：生成唯一的排队号，格式为窗口功能前缀+3位数字（SRD 4.5）
- 执行逻辑：
  ```sql
  -- 获取当天该窗口功能类型的最大排队号
  SELECT MAX(queue_number) AS max_queue_number
  FROM register_queue
  WHERE DATE(created_at) = CURDATE();

  -- 生成新排队号
  new_queue_number = 'A' + LPAD(CAST(SUBSTRING(max_queue_number, 2, 3) AS INT) + 1 AS VARCHAR), 3, '0');
  ```
- 规则说明：
  - 排队号格式：A001、A002、...（A为登记窗口前缀）
  - 每种窗口功能类型拥有独立队列
  - 当天排队号从001开始递增
  - 数字部分当天唯一，第二天重置为001

#### 规则9：更换批次库存释放规则
- 规则描述：更换批次时释放旧批次锁定的库存，锁定新批次库存
- 执行逻辑：
  ```sql
  -- 释放旧批次库存
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock - 1
  WHERE batch_id = ? AND locked_stock > 0;

  -- 锁定新批次库存
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock + 1
  WHERE batch_id = ? AND available_stock > 0;
  ```

#### 规则10：登记状态更新规则
- 规则描述：登记成功后更新预约状态为"已登记"（status=8），并记录批次ID和排队号
- 执行逻辑（SRD 5.2 node 4）：
  ```sql
  UPDATE appointment
  SET status = 8,
      current_window = 'REGISTER',
      batch_id = ?,
      queue_number = ?
  WHERE id = ?;
  ```

#### 规则10a：库存锁定释放机制
- 规则描述：登记时锁定库存后，需明确锁定消耗与释放的完整生命周期
- 锁定来源：登记时通过库存模块锁定指定批次的库存（locked_stock + 1）
- 锁定消耗：接种完成时确认扣减（locked_stock - 1, used_stock + 1）
- 锁定释放条件：
  - a. 接种完成 → 确认扣减（非释放）
  - b. 登记后三次过号 → 自动释放锁定的库存
  - c. 用户中途离开（窗口超时：超过5分钟未响应，由规则31的过号机制处理）→ 自动释放锁定的库存
  - d. 库存锁定超时（登记后2小时内未接种）→ 自动释放锁定的库存
- 注：库存锁定超时释放（2小时）由PRD-STOCK规则27统一管理，与窗口过号超时（5分钟）为不同机制。
- 释放操作：调用库存模块的释放接口，locked_stock - 1
- 释放后处理：将预约状态回退为 6（预检通过），通知用户重新排队
- 执行逻辑：
  ```sql
  -- 释放锁定的库存
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock - 1
  WHERE batch_id = ? AND locked_stock > 0;

  -- 回退预约状态
  UPDATE appointment
  SET status = 6, batch_id = NULL, queue_number = NULL
  WHERE id = ?;
  ```

### 5.2 批次业务规则

#### 规则11：批次号唯一性校验
- 规则描述：批次号必须唯一，不能重复
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM vaccine_batch WHERE batch_no = ?;
  ```
  结果必须为0
- 失败提示返回：`批次号已存在，请重新输入`

#### 规则12：批次有效期校验
- 规则描述：批次有效期必须大于生产日期
- 执行逻辑：`expiry_date > production_date`
- 失败提示返回：`有效期必须大于生产日期`

#### 规则13：批次库存非负校验
- 规则描述：批次库存不能为负数
- 执行逻辑：`available_stock >= 0 AND locked_stock >= 0`
- 失败提示返回：`库存不能为负数`

#### 规则14：批次状态流转规则
- 规则描述：批次状态只能按特定顺序流转
- 允许流转：
  - 正常（0）→ 临期（1）
  - 正常（0）→ 过期（2）：定时任务检测过期
  - 正常（0）→ 已销毁（3）
  - 临期（1）→ 过期（2）
  - 临期（1）→ 已销毁（3）
  - 过期（2）→ 已销毁（3）
- 禁止流转：
  - 已销毁（3）→ 其他状态（终态）

#### 规则15：批次自动过期规则
- 规则描述：批次过期后自动更新状态为"过期"（status=2）
- 执行逻辑：
  ```sql
  UPDATE vaccine_batch
  SET status = 2
  WHERE expiry_date < NOW() AND status IN (0, 1);
  ```

### 5.3 库存调拨规则

#### 规则16：调拨位置不能相同规则
- 规则描述：调出位置和调入位置不能相同
- 执行逻辑：`from_type != to_type OR from_id != to_id`
- 失败提示返回：`调出位置和调入位置不能相同`

#### 规则17：调拨库存充足规则
- 规则描述：调出位置的库存必须充足
- 执行逻辑：
  ```sql
  SELECT available_stock FROM hospital_vaccine_stock
  WHERE batch_id = ? AND hospital_id = ?;
  ```
  结果必须大于等于调拨数量
- 失败提示返回：`调出位置库存不足，无法调拨`

#### 规则18：调拨库存扣减规则
- 规则描述：调拨时扣减调出位置库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - ?
  WHERE batch_id = ? AND hospital_id = ? AND available_stock >= ?;
  ```

#### 规则19：调拨库存增加规则
- 规则描述：调拨时增加调入位置库存
- 执行逻辑：
  ```sql
  INSERT INTO hospital_vaccine_stock (hospital_id, batch_id, available_stock, locked_stock)
  VALUES (?, ?, ?, 0)
  ON DUPLICATE KEY UPDATE available_stock = available_stock + ?;
  ```

#### 规则20：调拨日志记录规则
- 规则描述：调拨操作必须记录日志
- 执行逻辑：
  ```sql
  INSERT INTO stock_transfer_log (transfer_no, batch_id, from_type, from_id, to_type, to_id, quantity, operator_id, transfer_time, remark)
  VALUES (?, ?, ?, ?, ?, ?, ?, ?, NOW(), ?);
  ```

### 5.4 批次销毁规则

#### 规则21：销毁批次状态规则
- 规则描述：只能销毁正常、临期、过期状态的批次
- 执行逻辑：`vaccine_batch.status IN (0, 1, 2)`
- 失败提示返回：`该批次已销毁，无法重复销毁`

#### 规则22：销毁数量校验
- 规则描述：销毁数量不能超过批次总库存
- 执行逻辑：销毁数量 <= (available_stock + locked_stock)
- 失败提示返回：`销毁数量不能超过批次总库存`

#### 规则23：销毁原因必填规则
- 规则描述：销毁原因必须填写
- 执行逻辑：dispose_reason IS NOT NULL AND dispose_reason != ''
- 失败提示返回：`请填写销毁原因`

#### 规则24：销毁库存扣减规则
- 规则描述：销毁时扣减批次库存，清空锁定库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - ?,
      locked_stock = 0
  WHERE batch_id = ? AND available_stock >= ?;
  ```

#### 规则25：销毁批次状态更新规则
- 规则描述：销毁后批次状态更新为"已销毁"（status=3）
- 执行逻辑：
  ```sql
  UPDATE vaccine_batch
  SET status = 3
  WHERE id = ?;
  ```

### 5.5 库存预警规则

#### 规则26：低库存预警规则
- 规则描述：剩余率低于20%时触发低库存预警
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, available_stock, locked_stock,
         (available_stock / (available_stock + locked_stock)) * 100 AS remaining_ratio
  FROM hospital_vaccine_stock
  WHERE (available_stock / (available_stock + locked_stock)) * 100 < 20;
  ```
- 处理动作：自动调用供应商接口补货

#### 规则27：临期预警规则
- 规则描述：有效期小于预警天数时触发临期预警
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, expiry_date, warning_days
  FROM vaccine_batch
  WHERE expiry_date - warning_days < NOW()
    AND status = 0;
  ```
- 处理动作：标记批次状态为临期（status=1），推送通知给库存医生

#### 规则28：过期预警规则
- 规则描述：有效期小于当前时间时触发过期预警（包含正常和在库状态的批次）
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, expiry_date
  FROM vaccine_batch
  WHERE expiry_date < NOW()
    AND status IN (0, 1);
  ```
- 处理动作：标记批次状态为过期（status=2），不可继续使用，需销毁

### 5.6 叫号/超时/过号机制（SRD 4.5）

#### 规则29：叫号机制
- 规则描述：登记医生点击"叫下一位"，系统按queue_order顺序叫号
- 执行逻辑：
  ```sql
  -- 查询下一个排队中的记录
  SELECT * FROM register_queue
  WHERE status = 0
  ORDER BY queue_order ASC
  LIMIT 1
  FOR UPDATE;

  -- 更新状态为已叫号
  UPDATE register_queue
  SET status = 1, called_time = NOW()
  WHERE id = ?;
  ```
- 通知规则（SRD 5.4）：叫号后发送APP推送通知，包含窗口号和排队号

#### 规则30：确认到号机制
- 规则描述：家长到达后，医生点击"确认到号"
- 执行逻辑：
  ```sql
  UPDATE register_queue
  SET status = 2, confirmed_time = NOW()
  WHERE id = ? AND status = 1;
  ```

#### 规则31：5分钟超时自动过号
- 规则描述：叫号后5分钟内未确认到号，系统自动标记为已过号
- 执行逻辑：
  ```sql
  -- 定时任务：每分钟检查超时记录
  UPDATE register_queue
  SET status = 3
  WHERE status = 1 AND called_time < DATE_SUB(NOW(), INTERVAL 5 MINUTE);
  ```

#### 规则32：三次过号自动取消
- 规则描述：同一预约累计过号3次，自动取消排队，状态回退为"已登记待分配"
- 执行逻辑：
  ```sql
  -- 查询累计过号次数（通过call_count字段记录）
  SELECT call_count FROM register_queue
  WHERE appointment_id = ? AND status IN (0, 1, 3)
  ORDER BY created_at DESC LIMIT 1;

  -- 第1次过号：回到队尾，APP通知，call_count = 1
  -- 第2次过号：回到队尾，再次APP通知，call_count = 2
  -- 第3次过号：自动取消，call_count = 3
  UPDATE register_queue SET status = 4, call_count = 3 WHERE id = ?;

  -- 预约状态回退为"已登记待分配"
  UPDATE appointment
  SET status = 8, current_window = 'REGISTER', batch_id = NULL, queue_number = NULL
  WHERE id = ?;

  -- 释放锁定的库存
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock - 1
  WHERE batch_id = ? AND locked_stock > 0;
  ```
- 通知规则（SRD 5.4）：过号时发送APP推送通知，包含过号信息和重新排队信息
- 家长需到登记窗口重新排队

#### 规则32a：过号回退后队列位置处理
- 规则描述：用户被叫号后未在规定时间内（5分钟）到达登记窗口，视为过号
- 过号次数记录：`register_queue.call_count` 字段，每次过号递增1
- 处理规则：
  1. 第一次过号：排队优先级降低，排到当前队列末尾（queue_order置为当前最大值+1），APP通知
  2. 第二次过号：同上，再次APP通知（提示剩余1次机会）
  3. 第三次过号：自动释放锁定的库存，移出登记队列（status=4），预约状态回退为 8（已登记待分配），通知用户重新排队
- 执行逻辑：
  ```sql
  -- 更新过号次数并回到队尾
  UPDATE register_queue
  SET status = 0,
      call_count = call_count + 1,
      queue_order = (SELECT COALESCE(MAX(queue_order), 0) + 1 FROM register_queue rq2 WHERE DATE(rq2.created_at) = CURDATE())
  WHERE id = ? AND call_count < 3;

  -- 第三次过号：释放库存并移出队列
  UPDATE register_queue SET status = 4, call_count = 3 WHERE id = ? AND call_count >= 3;
  ```

### 5.9 状态流转规则

#### 登记状态流转

```
status=7（预检通过）
    ↓ 登记医生登记
status=8（已登记）
    ↓ 登记医生核实信息
    ↓ 系统FEFO分配批次（仅status=0）
    ↓ 系统锁定库存
    ↓ 系统生成排队号
    ↓ 系统保存登记记录
    ↓ 更新appointment: status=8, batch_id, queue_number
status=8（已登记）
```

#### 排队状态流转（SRD 4.5）

```
queue_status=0（排队中）
    ↓ 医生点击"叫下一位"
queue_status=1（已叫号）
    ├─ 家长到达，医生点击"确认到号"
    │   ↓
    │ queue_status=2（已到号）
    │
    ├─ 5分钟超时未到号
    │   ↓
    │ queue_status=3（已过号）
    │   ├─ 第1次过号 → 回到队尾（queue_status=0），APP通知
    │   ├─ 第2次过号 → 回到队尾（queue_status=0），APP通知
    │   └─ 第3次过号 → queue_status=4（已取消）
    │                   appointment回退为"已登记待分配"，需到登记窗口重新排队
    │
    └─ 手动取消
        ↓
        queue_status=4（已取消）
```

#### 批次状态流转

```
status=0（正常）
    ↓ 批次即将过期
status=1（临期）
    ↓ 批次过期
status=2（过期）
    ↓ 库存医生销毁
status=3（已销毁）

其他流转：
status=0（正常）
    ↓ 库存医生销毁
status=3（已销毁）

status=1（临期）
    ↓ 库存医生销毁
status=3（已销毁）
```

### 7.4 权限校验流程

```
用户请求
  ↓
解析Token获取用户ID
  ↓
查询用户角色：sys_user_role WHERE user_id = ?
  ↓
查询角色权限：sys_role_permission WHERE role_id IN (...)
  ↓
判断请求接口是否在权限列表
  ↓
  ├─ 有权限 → 继续执行
  └─ 无权限 → 返回403 Forbidden
  ↓
数据访问权限校验
  ↓
  ├─ DOCTOR_REGISTER类型 → WHERE doctor_id = current_doctor_id OR status = 7
  ├─ DOCTOR_STOCK类型 → 无限制
  └─ 管理员类型 → 无限制
  ↓
执行业务逻辑
  ↓
返回响应结果
```

## 8. 异常场景

### 8.1 业务异常

#### E-REGISTER-001：预约状态异常

**场景描述：** 预约当前状态不允许登记操作

**触发条件：** appointment.status != 7

**错误码：** 4101
**错误消息：** `该预约状态不允许登记，当前状态：{status_text}，请核实后重试`
**HTTP状态码：** 403 Forbidden

**处理建议：**
- 显示当前状态给医生
- 引导医生查看预约详情
- 只有状态为"预检通过"的预约可以登记

---

#### E-REGISTER-002：预检结果未通过

**场景描述：** 预约的预检结果为未通过，无法登记

**触发条件：**
```sql
SELECT result FROM pre_check_record WHERE appointment_id = ?;
```
返回结果 != 'PASS'

**错误码：** 4102
**错误消息：** `该预约预检未通过，无法登记，请咨询预检医生后处理`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示预检未通过信息
- 引导医生查看预检详情
- 引导医生联系预检医生

---

#### E-REGISTER-003：无可用批次

**场景描述：** 系统查询不到可用的批次进行分配

**触发条件：**
```sql
SELECT COUNT(*) FROM vaccine_batch b
JOIN hospital_vaccine_stock s ON b.id = s.batch_id
WHERE b.vaccine_id = ?
  AND s.hospital_id = ?
  AND b.status = 0
  AND s.available_stock > 0
  AND b.expiry_date > NOW();
```
返回结果为0

**错误码：** 4103
**错误消息：** `该疫苗暂无可用批次，无法登记，建议家长重新预约`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息给医生和家长
- 建议家长重新预约（SRD 5.2）
- 不继续登记流程

---

**触发条件：** 库存模块接口超时或返回非200状态码

**错误码：** 4151
**错误消息：** `库存服务暂时不可用，请稍后重试`
**HTTP状态码：** 503 Service Unavailable

**处理建议：**
- 显示友好错误消息
- 前端提供"重试"按钮
- 不修改预约状态，保持为预检通过
- 后端记录错误日志并告警运维

---

#### E-REGISTER-106：并发冲突（库存分配）

**场景描述：** 两个医生同时为同一批次分配库存，行级锁等待超时

**触发条件：** `SELECT ... FOR UPDATE` 等待锁超时（超过3秒）

**错误码：** 4152
**错误消息：** `系统繁忙，请稍后重试`
**HTTP状态码：** 409 Conflict

**处理建议：**
- 使用乐观锁重试机制，最多重试3次
- 每次重试间隔200ms
- 3次重试仍失败则返回错误提示
- 引导医生重新分配批次

---

#### E-REGISTER-107：未登录异常

**场景描述：** 用户未携带Token或Token无效

**错误码：** 401
**HTTP状态码：** 401 Unauthorized

**处理建议：**
- 前端拦截401响应，自动跳转登录页

---

#### E-REGISTER-108：无权限异常

**场景描述：** 用户已登录但无权访问该资源

**错误码：** 403
**HTTP状态码：** 403 Forbidden

**处理建议：**
- 前端提示"无权限访问该功能"
- 引导用户联系管理员分配权限

---

### 8.3 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息、请求参数、医生信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-REGISTER-001~017）
  │   ↓
  │   返回友好错误消息给医生
  │   显示处理建议
  │   记录业务异常日志
  │
  ├─ 系统异常（E-REGISTER-101~108）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```
