## 1. 模块概述

### 1.1 模块定位

预约模块是疫苗管理系统的核心模块之一，负责处理家长线上预约接种的预约管理业务。本模块聚焦于预约的创建、查询、取消及状态管理，是用户端与后续接种流程的入口。

> **模块归属说明：** 签到、预检、登记、接种、留观等流程操作归属于 PRD-FLOW（流程管理模块），本模块中的 F-APPOINTMENT-005~012 为跨模块引用功能，详细定义见 PRD-FLOW 对应章节。

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 预约创建、预约查询、预约取消 | 疫苗目录管理（属于疫苗模块） |
| 预约状态流转、窗口指引 | 儿童档案管理（属于用户模块） |
| 预约验证、规则检查 | 排班管理（属于排班模块） |
| 预约过期自动处理 | 库存扣减（属于库存模块） |
| | 签到/预检/登记/接种/留观操作（→ PRD-FLOW） |
| | 各窗口队列查询（→ PRD-FLOW） |

### 1.3 涉及角色

| 角色 | 角色 | 使用场景 |
|------|------|----------|
| USER | 家长（用户） | 创建预约、查询预约、取消预约、查看指引 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 查看预约统计、管理预约配置 |
| SYSTEM | 系统 | 预约过期自动处理 |

> **注：** DOCTOR_SIGNIN、DOCTOR_PRECHECK、DOCTOR_REGISTER、DOCTOR_VACCINATE、DOCTOR_OBSERVE 等窗口医生角色在 PRD-FLOW 中定义。本模块 F-005~012 引用这些角色时，详细权限见 PRD-FLOW 第 7 章。

### 1.4 核心业务价值

- **提升用户体验**：家长可提前预约，减少现场等待时间
- **优化医院效率**：通过预约管理，平衡医院资源，提高服务效率
- **流程可视化**：实时窗口指引，让家长清晰了解当前进度
- **数据可追溯**：完整记录预约全流程，支持统计分析和问题追溯

### 2.2 功能详情

#### F-APPOINTMENT-001: 创建预约

**功能描述：** 用户通过APP提交疫苗接种预约申请，系统进行规则校验后生成预约记录。

**输入参数：**
- 用户ID（从会话中获取）
- 儿童ID（必填）
- 疫苗ID（必填）
- 预约日期（必填，格式：YYYY-MM-DD）
- 预约时段（必填，30分钟粒度，格式："08:00-08:30"、"08:30-09:00"等）

**输出结果：**
- 预约创建成功：返回预约ID、预约详情
- 预约创建失败：返回失败原因（错误码+错误消息）

**映射API：** POST /api/user/appointment

**校验规则：**
1. 用户必须已登录且未被冻结
2. 儿童档案必须存在且属于当前用户
3. 疫苗必须存在且处于上架状态
4. 预约日期必须是未来日期（不能预约当天及以前的日期）
5. 预约时段必须有效（30分钟粒度，如"08:00-08:30"、"08:30-09:00"等）
6. 该时段预约人数必须未达到上限
7. 用户在预约日期前必须没有相同疫苗的未完成预约
8. 唯一约束：(parent_id, child_id, vaccine_id, appointment_date, time_slot) 不允许重复预约

#### F-APPOINTMENT-002: 查询预约详情

**功能描述：** 根据预约ID查询单个预约的完整详细信息。

**输入参数：**
- 预约ID（必填）
- 用户ID（从会话中获取，用于权限验证）

**输出结果：**
- 预约详情对象（包含所有预约字段及关联信息）

**映射API：** GET /api/user/appointment/{appointmentId}

**权限规则：**
1. 用户只能查询自己的预约
2. 医生只能查询在自己窗口处理过的预约
3. 系统管理员和业务管理医生可查询所有预约

---

#### F-APPOINTMENT-003: 查询预约列表

**功能描述：** 查询用户的预约记录列表，支持分页和状态筛选。

**输入参数：**
- 用户ID（从会话中获取）
- 状态筛选（可选，枚举值：ALL/IN_PROGRESS/COMPLETED/CANCELLED）
- 分页参数：
  - page（1-based，默认1）
  - pageSize（默认20，最大100）
  - sortBy（默认 created_at）
  - sortOrder（asc/desc，默认 desc）

**输出结果：**
- 预约列表（按 created_at 倒序）
- 分页信息：{list, total, page, pageSize, totalPages}

**映射API：** GET /api/user/appointments?status={status}&page={page}&pageSize={pageSize}&sortBy={sortBy}&sortOrder={sortOrder}

**筛选逻辑：**
- ALL：返回所有状态的预约
- IN_PROGRESS：返回进行中的预约（状态值：1,6,7,8,10）
- COMPLETED：返回已完成的预约（状态值：2）
- CANCELLED：返回已取消的预约（状态值：3,4,9）

#### F-APPOINTMENT-004: 取消预约

**功能描述：** 用户主动取消预约。status=1阶段的预约取消无需释放库存（此时未进入登记环节，未锁定具体批次库存）。

**输入参数：**
- 预约ID（路径参数）
- 用户ID（从会话中获取）
- 取消原因（必填，JSON Body: `{"reason": "临时有事，无法前往"}`）

**输出结果：**
- 取消成功：返回取消确认信息
- 取消失败：返回失败原因

**映射API：** PUT /api/user/appointment/{id}/cancel

**业务规则：**
1. 只能取消自己的预约
2. 只有状态为"已预约"（status=1）的预约可以取消
3. 已签到及后续状态的预约不能取消
4. status=1阶段的预约取消无需释放库存（此时未进入登记环节，未锁定具体批次库存）
5. **爽约判定：** 取消时间为预约日期当天或之后，视为爽约，`no_show_count += 1`；预约日期之前取消不计入爽约
6. **爽约冻结：** `no_show_count >= 3` 时冻结用户预约权限7天，冻结期间无法创建新预约
7. **解冻机制：** 冻结到期后自动解冻（下次请求时校验 `freeze_end_time > NOW()`）
8. **重置规则：** 冻结解除后 `no_show_count` 不重置（累计计算）
9. **手动解冻：** SUPER_ADMIN 可通过后台管理手动解除冻结，立即恢复用户预约权限

---

#### F-APPOINTMENT-005: 获取窗口指引

**功能描述：** 根据预约当前状态，获取下一步窗口指引信息。

**输入参数：**
- 预约ID（必填）
- 用户ID（从会话中获取）

**输出结果：**
- 预约ID
- 当前状态（status值）
- 当前状态描述（statusText）
- 下一步指引（nextGuide）：
  - nextAction：下一步操作名称
  - guideMessage：指引消息
  - windowCode：窗口编码
  - windowName：窗口名称
  - windowFunctionType：窗口职能类型

**映射API：** GET /api/user/appointment/{id}/guide

**指引规则：** 见[5.3 窗口指引规则](#53-窗口指引规则)

#### F-APPOINTMENT-006: 获取排队信息

**功能描述：** 获取预约当前应去窗口的排队信息，包括当前排队人数、预估等待时间等。

**输入参数：**
- 预约ID（必填）
- 用户ID（从会话中获取）

**输出结果：**
- windowCode：窗口编码
- windowName：窗口名称
- windowFunctionType：窗口职能类型
- currentQueue：当前排队人数
- capacity：窗口容量
- estimatedWaitTime：预估等待时间（分钟）

**映射API：** GET /api/user/appointment/{id}/queue

**计算规则：**
- currentQueue = 统计该窗口职能下待处理的预约数（除当前预约外）
- estimatedWaitTime = currentQueue × 该窗口预估办理时间

#### F-APPOINTMENT-013: 预约过期自动处理

**功能描述：** 定时扫描过期预约，自动标记为爽约并释放资源。

**触发条件：** 当前时间 > 预约日期 time_slot 结束时间 + 30分钟 且 status = 1（已预约）

**执行逻辑：**
1. 查询所有已过时段结束时间30分钟仍未签到的预约
2. 批量更新 status=4（已过期）
3. `no_show_count += 1`
4. status=1阶段的预约过期无需释放库存（此时未进入登记环节，未锁定具体批次库存）
5. 记录过期原因
6. 若 `no_show_count >= 3`，冻结用户预约权限7天（设置 `sys_user.freeze_end_time`）

**执行方式：** 定时任务，每5分钟执行一次

**爽约冻结规则（SRD 5.4）：**
- 爽约判定：time_slot 结束时间 + 30分钟后仍未签到
- 3次爽约 → 冻结预约权限7天
- 冻结字段：`sys_user.freeze_end_time`
- 冻结期间无法创建新预约（预约接口校验 `freeze_end_time > NOW()`）
- 冻结到期后自动解冻（下次请求时校验）

**映射API：** 内部定时任务，无外部 API。提供管理端手动触发接口 `POST /api/admin/appointment/expire`

## 4. 用户操作流程

### 4.1 用户端流程：创建预约

```
┌─────────────────────────────────────────────────────────────┐
│  步骤1：打开疫苗预约页面                                  │
│  - 用户登录APP                                            │
│  - 点击"预约接种"                                         │
│  - 系统显示疫苗列表                                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤2：选择疫苗                                          │
│  - 浏览疫苗列表（按类别分组显示）                          │
│  - 点击"筛选"按钮，选择疫苗类别（可选）                   │
│  - 查看疫苗详情（弹窗显示）                                │
│  - 点击"立即预约"按钮                                      │
│  - 系统跳转到预约详情页面                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤3：选择预约日期                                      │
│  - 显示日历组件（未来30天可预约）                          │
│  - 选择预约日期（只能选择未来日期）                        │
│  - 选择时段（上午/下午）                                   │
│  - 查看剩余名额                                            │
│  - 点击"下一步"按钮                                        │
│  - 系统跳转到选择儿童页面                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤4：选择儿童                                          │
│  - 显示当前用户的儿童列表                                  │
│  - 系统标记适龄儿童（√）和不适龄儿童（×）                 │
│  - 系统显示适龄原因（如"超出年龄范围"）                    │
│  - 选择适龄儿童                                            │
│  - 点击"下一步"按钮                                        │
│  - 系统跳转到预约确认页面                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤5：确认预约                                          │
│  - 核对预约信息（儿童、疫苗、日期、时段）                  │
│  - 阅读温馨提示                                            │
│  - 点击"提交预约"按钮                                      │
│  - 系统进行校验：                                          │
│    • 用户是否被冻结                                        │
│    • 儿童档案是否完善                                      │
│    • 疫苗是否上架                                          │
│    • 预约时间是否有效                                      │
│    • 该时段是否满员                                        │
│    • 是否有重复预约                                        │
│  - 校验通过，生成预约记录                                  │
│  - 系统返回预约成功信息（预约号、预约详情）                │
│  - 系统跳转到预约详情页面                                  │
└─────────────────────────────────────────────────────────────┘
```

## 5. 业务规则

### 5.1 预约创建规则

#### 规则1：用户状态校验
- 规则描述：只有正常状态且未被冻结的用户可以创建预约
- 执行逻辑：
  ```sql
  SELECT status, freeze_end_time FROM sys_user WHERE id = ?;
  ```
  - `status = 0`（正常）
  - `freeze_end_time IS NULL OR freeze_end_time < NOW()`（未冻结或冻结期已过）
- 失败提示返回：`用户账户已被冻结，请稍后重试`

#### 规则2：儿童档案归属校验
- 规则描述：儿童档案必须存在且属于当前用户
- 执行逻辑：
  ```sql
  SELECT id FROM child_profile WHERE id = ? AND parent_id = ?;
  ```
- 失败提示返回：`儿童档案不存在或不属于当前用户`

#### 规则3：疫苗上架状态校验
- 规则描述：疫苗必须存在且处于上架状态
- 执行`status = 0`（上架）的疫苗
- 失败提示返回：`该疫苗暂未上架，无法预约`

#### 规则4：预约日期有效性校验
- 规则描述：预约日期必须是未来日期
- 执行逻辑：`appointment_date > CURDATE()`
- 失败提示返回：`预约日期必须是未来日期`

#### 规则5：预约时段有效性校验
- 规则描述：预约时段必须符合30分钟粒度格式
- 有效时段格式：`"HH:mm-HH:mm"`，如"08:00-08:30"、"08:30-09:00"等
- 时段范围：08:00-12:00 和 14:00-17:00 之间的30分钟时段
- 失败提示返回：`预约时段无效`

#### 规则6：时段容量校验
- 规则描述：该时段预约人数不能超过配置的上限
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM appointment
  WHERE appointment_date = ? AND time_slot = ? AND status = 1;
  ```
  结果必须小于配置上限
- 失败提示返回：`该时段预约已满，请选择其他时段`

#### 规则7：重复预约校验（唯一约束）
- 规则描述：(parent_id, child_id, vaccine_id, appointment_date, time_slot) 不允许重复预约
- 注：status=9（预检未通过）的预约不计入"未完成预约"约束，因为预检未通过为终态，不影响用户重新预约。
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM appointment a
  WHERE a.parent_id = ?
    AND a.child_id = ?
    AND a.vaccine_id = ?
    AND a.appointment_date = ?
    AND a.time_slot = ?;
  ```
  结果必须为0
- 失败提示返回：`您已有该疫苗在同一时段的预约，请勿重复预约`

#### 规则8：儿童年龄适配校验
- 规则描述：儿童年龄必须在疫苗的适龄范围内
- 执行逻辑：
  ```sql
  SELECT min_age, max_age FROM vaccine WHERE id = ?;
  ```
  计算：儿童月龄 >= min_age AND 儿童月龄 <= max_age
- 失败提示返回：`儿童年龄不在该疫苗的适龄范围内`

### 5.2 预约取消规则

#### 规则9：预约归属校验
- 规则描述：只能取消自己的预约
- 执行逻辑：`appointment.parent_id = current_user_id`
- 失败提示返回：`无权操作该预约`

#### 规则10：预约状态校验
- 规则描述：只有状态为"已预约"（status=1）的预约可以取消
- 执行逻辑：`appointment.status = 1`
- 失败提示返回：`该预约已进行到后续环节，无法取消`

#### 规则11：库存释放规则
- 规则描述：status=1阶段的预约取消无需释放库存，因为此时未进入登记环节，appointment.batch_id为NULL，未锁定具体批次库存。
- 执行逻辑：
  ```sql
  -- 注意：以下SQL仅在 status > 1（已登记/已签到等，已锁定具体批次库存）时执行
  -- status=1阶段的预约取消无需释放库存（此时 batch_id 为 NULL，未锁定具体批次库存）
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock - 1
  WHERE batch_id = ? AND locked_stock > 0;
  ```

#### 规则12：爽约次数累加规则
- 规则描述：取消预约时，若取消时间为预约日期当天或之后，视为爽约，爽约次数+1
- 执行逻辑：
  ```sql
  UPDATE appointment SET no_show_count = no_show_count + 1 WHERE id = ?;
  UPDATE sys_user SET no_show_count = no_show_count + 1 WHERE id = ?;
  ```
- 预约日期之前取消不计入爽约次数

#### 规则13：爽约冻结规则
- 规则描述：爽约次数达到3次，冻结用户预约权限7天
- 冻结触发条件：`no_show_count >= 3`
- 冻结时长：7天
- 冻结效果：冻结期间无法创建新预约（预约接口校验 `freeze_end_time > NOW()`）
- 解冻方式：冻结到期后自动解冻（下次请求时校验）
- 重置规则：冻结解除后 `no_show_count` 不重置（累计计算）
- 执行逻辑：
  ```sql
  UPDATE sys_user
  SET status = 1, freeze_start_time = NOW(), freeze_end_time = DATE_ADD(NOW(), INTERVAL 7 DAY)
  WHERE id = ? AND no_show_count >= 3 AND (freeze_end_time IS NULL OR freeze_end_time <= NOW());
  ```

#### 规则14：预约过期自动取消规则（爽约检测，SRD 5.4）
- 规则描述：定时扫描过期预约，基于 time_slot 结束时间 + 30分钟判定爽约
- 触发条件：`appointment.appointment_date <= CURDATE()` 且当前时间 > `time_slot` 结束时间 + 30分钟 且 `status = 1`
- 执行逻辑：
  ```sql
  UPDATE appointment
  SET status = 4, no_show_count = no_show_count + 1
  WHERE appointment_date <= CURDATE()
    AND status = 1
    AND CONCAT(appointment_date, ' ', SUBSTRING_INDEX(time_slot, '-', -1)) < DATE_SUB(NOW(), INTERVAL 30 MINUTE);
  ```
- 若 `no_show_count >= 3`，同时冻结用户预约权限：
  ```sql
  UPDATE sys_user
  SET status = 1, freeze_start_time = NOW(), freeze_end_time = DATE_ADD(NOW(), INTERVAL 7 DAY)
  WHERE id = ? AND no_show_count >= 3 AND (freeze_end_time IS NULL OR freeze_end_time <= NOW());
  ```
- 执行方式：定时任务，每5分钟执行一次
- 爽约处理：预约过期计入爽约次数（no_show_count += 1）

### 5.3 签到规则

#### 规则15：预约状态校验
- 规则描述：预约状态必须为"已预约"（status=1）
- 执行逻辑：`appointment.status = 1`

#### 规则16：预约日期校验

- 执行逻辑：`appointment.appointment_date <= CURDATE()`

- 失败提示返回：`身份证号不匹配，请核对后重试`

#### 规则18：签到状态更新规则
- 规则描述：签到成功后更新预约状态为"已签到"（status=6）
- 执行逻辑：
  ```sql
  UPDATE appointment
  SET status = 6,
      current_window = 'SIGNIN',
      sign_in_time = NOW()
  WHERE id = ?;
  ```

### 5.4 窗口指引规则

| 当前状态 | status值 | 下一步窗口 | 窗口职能 | 指引消息 | 显示排队 |
|----------|----------|------------|----------|----------|----------|
| 已预约 | 1 | 签到窗口 | SIGNIN | 您已成功预约，请到签到窗口办理签到 | 否 |
| 已签到 | 6 | 预检窗口 | PRECHECK | 签到成功，请到预检窗口等待预检 | 是 |
| 预检通过 | 7 | 登记窗口 | REGISTER | 预检通过，请到登记窗口排队 | 是 |
| 已登记 | 8 | 接种窗口 | VACCINATE | 登记完成，请到接种窗口等待接种 | 是 |
| 留观中 | 10 | 留观室 | OBSERVE | 接种完成，请在留观室观察30分钟 | 否 |
| 已完成 | 2 | 无 | - | 接种流程已完成，感谢您的配合 | 否 |
| 已取消 | 3 | 无 | - | 该预约已取消 | 否 |
| 已过期 | 4 | 无 | - | 该预约已过期，请重新预约 | 否 |
| 预检未通过 | 9 | 无 | - | 预检未通过，请咨询医生后重新预约 | 否 |

**指引逻辑实现：**
```sql
SELECT status,
       CASE status
           WHEN 1 THEN 'SIGNIN'
           WHEN 6 THEN 'PRECHECK'
           WHEN 7 THEN 'REGISTER'
           WHEN 8 THEN 'VACCINATE'
           WHEN 10 THEN 'OBSERVE'
           ELSE NULL
       END AS next_window_type
FROM appointment
WHERE id = ?;
```

### 5.5 队列查询规则

> **归属说明：** 队列查询规则归属于 PRD-FLOW，权威定义见 PRD-FLOW 第 5 章。本节仅作为补充参考。

#### 预检队列查询规则
- 规则描述：查询待预检的预约（已签到但未预检）
- 执行逻辑：
  ```sql
  SELECT a.*, cp.name AS child_name, s.signin_time
  FROM appointment a
  JOIN child_profile cp ON a.child_id = cp.id
  JOIN pre_check_record pcr ON a.id = pcr.appointment_id
  WHERE a.appointment_date = ?
    AND a.status = 6
  ORDER BY pcr.created_at ASC;
  ```

#### 登记队列查询规则
- 规则描述：查询待登记的预约（预检通过但未登记）
- 执行逻辑：
  ```sql
  SELECT a.*, cp.name AS child_name, pcr.created_at AS precheck_time
  FROM appointment a
  JOIN child_profile cp ON a.child_id = cp.id
  JOIN pre_check_record pcr ON a.id = pcr.appointment_id
  WHERE a.appointment_date = ?
    AND a.status = 7
  ORDER BY pcr.created_at ASC;
  ```

#### 接种队列查询规则
- 规则描述：查询待接种的预约（已登记但未接种）
- 执行逻辑：
  ```sql
  SELECT a.*, cp.name AS child_name, rq.created_at, vb.batch_no
  FROM appointment a
  JOIN child_profile cp ON a.child_id = cp.id
  JOIN register_queue rq ON a.id = rq.appointment_id
  JOIN vaccine_batch vb ON a.batch_id = vb.id
  WHERE a.appointment_date = ?
    AND a.status = 8
  ORDER BY rq.queue_number ASC;
  ```

#### 留观队列查询规则
- 规则描述：查询留观中的预约（已接种但留观未结束）
- 执行逻辑：
  ```sql
  SELECT a.*, cp.name AS child_name, vr.vaccinate_time, vr.injection_id
  FROM appointment a
  JOIN child_profile cp ON a.child_id = cp.id
  JOIN vaccination_record vr ON a.id = vr.appointment_id
  WHERE a.appointment_date = ?
    AND a.status = 10
  ORDER BY vr.vaccinate_time ASC;
  ```

### 5.6 状态流转规则

#### 预约状态流转图

```
status=1（已预约）
    ↓ 用户签到
status=6（已签到）
    ↓ 预检通过
status=7（预检通过）
    ↓ 登记完成
status=8（已登记）
    ↓ 接种完成
status=10（留观中）
    ↓ 留观结束
status=2（已完成）

异常分支：
status=3（已取消）← 用户主动取消
status=4（已过期）← 系统自动过期（预约时间已过且未签到）
status=9（预检未通过）← 预检评估未通过
```

#### 状态流转约束

| 当前状态 | 可流转状态 | 触发条件 | 流转角色 |
|----------|------------|----------|----------|
| 1（已预约） | 6（已签到） | 用户签到 | DOCTOR_SIGNIN |
| 1（已预约） | 3（已取消） | 用户取消预约 | USER |
| 1（已预约） | 4（已过期） | 预约时间已过且未签到 | SYSTEM |
| 6（已签到） | 7（预检通过） | 预检评估通过 | DOCTOR_PRECHECK |
| 6（已签到） | 9（预检未通过） | 预检评估未通过 | DOCTOR_PRECHECK |
| 7（预检通过） | 8（已登记） | 登记完成 | DOCTOR_REGISTER |
| 8（已登记） | 10（留观中） | 接种完成 | DOCTOR_VACCINATE |
| 10（留观中） | 2（已完成） | 留观结束 | DOCTOR_OBSERVE |

**状态流转校验规则：**
- 每次状态变更前，必须校验当前状态是否允许流转到目标状态
- 状态变更必须记录操作时间和操作人
- 状态变更必须生成操作日志

### 7.4 权限校验流程

```
用户请求
  ↓

  ↓

  ↓
查询角色权限：sys_role_permission WHERE role_id IN (...)
  ↓
判断请求接口是否在权限列表
  ↓
  ├─ 有权限 → 继续执行

  ↓

  └─ 管理员类型 → 无限制
  ↓
执行业务逻辑
  ↓
返回响应结果
```

## 8. 异常场景

### 8.1 业务异常

#### E-APPOINTMENT-001：用户已冻结

**场景描述：** 用户爽约次数达到3次，账户被冻结7天，无法创建预约

**触发条件：**
```sql
SELECT freeze_end_time FROM sys_user WHERE id = ?
```
返回值不为NULL且大于当前时间

**错误码：** 3001
**错误消息：** `您的账户已被冻结，解冻时间为：{freeze_end_time}，请解冻后再预约`
**HTTP状态码：** 403 Forbidden

**处理建议：**
- 显示解冻时间给用户
- 引导用户联系客服或等待解冻
- 系统自动解冻：定时任务检查freeze_end_time，到期自动清空

---

#### E-APPOINTMENT-002：儿童档案不存在

**场景描述：** 用户选择了一个不存在的儿童ID或儿童ID不属于当前用户

**触发条件：**
```sql
SELECT COUNT(*) FROM child_profile WHERE id = ? AND parent_id = ?
```
返回结果为0

**错误码：** 3002
**错误消息：** `儿童档案不存在或您无权操作该档案`
**HTTP状态码：** 404 Not Found

**处理建议：**
- 引导用户刷新页面
- 引导用户返回儿童档案列表重新选择
- 检查用户session是否过期

---

#### E-APPOINTMENT-003：疫苗未上架

**场景描述：** 用户选择的疫苗当前未上架，无法预约

**触发条件：**
```sql
SELECT status FROM vaccine WHERE id = ?
```
返回值不等于0（上架状态）

**错误码：** 3003
**错误消息：** `该疫苗暂未上架，无法预约，请选择其他疫苗`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息给用户
- 引导用户选择其他疫苗
- 显示可预约的疫苗列表

---

#### E-APPOINTMENT-004：预约日期无效

**场景描述：** 用户选择的预约日期不是未来日期

**触发条件：** appointment_date <= CURDATE()

**错误码：** 3004
**错误消息：** `预约日期必须是未来日期，请重新选择`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息给用户
- 引导用户重新选择预约日期
- 日历组件限制只能选择未来日期

---

#### E-APPOINTMENT-005：预约时段无效

**场景描述：** 用户选择的预约时段不在有效范围内

**触发条件：** time_slot 不符合 "HH:mm-HH:mm" 30分钟粒度格式

**错误码：** 3005
**错误消息：** `预约时段无效，请选择有效的30分钟时段`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息给用户
- 引导用户重新选择时段
- 前端时段选择器限制只能选择有效时段

---

#### E-APPOINTMENT-006：时段预约已满

**场景描述：** 用户选择的时段预约人数已达到配置上限

**触发条件：**
```sql
SELECT COUNT(*) FROM appointment
```

返回结果 >= 配置上限

**错误码：** 3006

**处理建议：**

#### E-APPOINTMENT-007：存在重复预约

**场景描述：** 用户在同一时段已有相同儿童相同疫苗的预约

**触发条件：**
```sql
SELECT COUNT(*) FROM appointment a
WHERE a.parent_id = ?
  AND a.child_id = ?
  AND a.vaccine_id = ?
  AND a.appointment_date = ?
  AND a.time_slot = ?;
```
返回结果 > 0

**错误码：** 3007
**错误消息：** `您已有该疫苗在同一时段的预约，请勿重复预约`
**HTTP状态码：** 409 Conflict

**处理建议：**
- 显示重复预约信息给用户
- 引导用户查看已有预约
- 引导用户取消重复预约后再重新预约

---

#### E-APPOINTMENT-008：儿童年龄不匹配

**场景描述：** 儿童年龄不在疫苗的适龄范围内

**触发条件：**
```sql
SELECT min_age, max_age FROM vaccine WHERE id = ?;
```
计算：儿童月龄 < min_age OR 儿童月龄 > max_age

**错误码：** 3008
**错误消息：** `儿童年龄不在该疫苗的适龄范围内，该疫苗适用于{min_age}月龄至{max_age}月龄，您的孩子{child_age}月龄`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示适龄范围和当前儿童年龄
- 引导用户选择其他适合儿童年龄的疫苗
- 前端显示适龄疫苗推荐

#### E-APPOINTMENT-011：预约状态异常（含重复签到）

**场景描述：** 预约当前状态不允许执行该操作，包括已签到后重复签到

**触发条件：**
- 取消预约时：status != 1
- 签到时：status != 1（含 status >= 6 的重复签到场景）
- 其他状态流转时的状态校验失败

**错误码：** 3011
**错误消息：** `该预约已签到或状态异常，当前状态：{status_text}，无法执行：{operation}`
**HTTP状态码：** 403 Forbidden

**处理建议：**
- 显示当前状态和操作说明
- 如为重复签到，显示签到时间并引导医生查看预约详情
- 引导用户查看预约详情或联系医生处理

#### E-APPOINTMENT-012：预约已过期

**场景描述：** 预约时间已过且未签到

**触发条件：** appointment.appointment_date < CURDATE() AND status = 1

**错误码：** 3012

**HTTP状态码：** 410 Gone

**处理建议：**
- 显示预约日期
- 引导用户重新预约
- 系统自动更新状态为status=4（已过期）

**处理建议：**
- 显示取消原因（如有）

### 8.3 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息、请求参数、用户信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-APPOINTMENT-001~015）
  │   ↓
  │   返回友好错误消息给用户
  │   显示处理建议
  │   记录业务异常日志
  │
  ├─ 系统异常（E-APPOINTMENT-101~106）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```

### 8.4 重试机制

**可重试的异常：**
- E-APPOINTMENT-101：数据库连接异常
- E-APPOINTMENT-102：并发冲突

**重试策略：**
- 最大重试次数：3次
- 重试间隔：1秒、2秒、4秒（指数退避）
- 超时时间：30秒

**重试逻辑：**
```
重试次数 = 0
WHILE 重试次数 < 3
  尝试执行操作
  成功 → 返回结果
  失败且可重试 → 重试次数+1，等待后继续
  失败且不可重试 → 抛出异常
END WHILE
抛出异常（重试失败）
```
