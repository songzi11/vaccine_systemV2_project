## 1. 模块概述

### 1.1 模块定位

库存管理模块负责医院内疫苗批次的全生命周期库存管理，包括库存查询、库存调拨、批次销毁、库存预警、库存汇总等功能。

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 批次库存查询 | 疫苗目录管理（属于疫苗模块） |
| 库存调拨管理（含乐观锁并发控制） | 登记时批次分配（属于登记模块） |
| 批次销毁操作 | 接种时库存扣减（属于接种模块） |
| 库存预警查看与处理 | 预检评估（属于预检模块） |
| 库存汇总统计 | 用户通知推送（属于通知模块） |
| FEFO批次分配策略 | 公告管理（属于公告模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| DOCTOR_STOCK | 库存管理医生 | 库存查询、调拨、销毁、预警查看 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 库存统计查看 |

### 1.4 核心业务价值

- **库存实时监控**：实时掌握各批次库存状态，确保库存充足
- **库存灵活调拨**：支持医院内部不同位置之间的库存调拨，优化资源配置
- **批次规范管理**：规范批次销毁流程，确保质量安全
- **预警及时响应**：自动监控低库存和临期批次，及时预警
- **数据完整可追溯**：完整记录库存变动历史，支持追溯审计

### 1.5 业务场景

**场景1：库存管理医生查看某疫苗的总库存**
```
库存管理医生登录终端
  ↓
进入库存汇总页面
  ↓
选择疫苗
  ↓
系统显示该疫苗所有批次的库存信息
  ↓
系统计算总库存、可用库存、锁定库存
  ↓
系统显示剩余率和使用率
```

**场景2：库存管理医生处理临期预警**
```
库存管理医生登录终端
  ↓
进入批次预警页面
  ↓
系统显示触发预警的批次列表
  ↓
库存管理医生查看临期预警批次
  ↓
库存管理医生标记已处理
  ↓
库存管理医生发起调拨，优先使用临期批次
```

### 2.2 功能详情

#### F-STOCK-001: 查询库存汇总

**功能描述：** 查询医院疫苗库存汇总信息，支持按疫苗维度汇总。

**输入参数：**
- 疫苗ID（可选，不传则查询所有疫苗）
- 医院ID（必填，固定为1）

**输出结果：**
- 库存汇总列表：
  - 疫苗ID
  - 疫苗名称
  - 总库存（所有批次合计）
  - 可用库存（所有批次合计）
  - 锁定库存（所有批次合计）
  - 剩余率
  - 使用率
  - 是否预警
  - 预警类型（如有）

**映射API：** GET /api/stock/summary?vaccineId={vaccineId}&hospitalId={hospitalId}

**查询逻辑：**
```sql
SELECT vs.id, vs.vaccine_id, v.vaccine_name, vs.total_stock, vs.available_stock,
       (vs.available_stock / vs.total_stock) * 100 AS remaining_ratio,
       ((vs.total_stock - vs.available_stock) / vs.total_stock) * 100 AS usage_ratio
FROM hospital_vaccine_summary vs
JOIN vaccine v ON vs.vaccine_id = v.id
WHERE vs.hospital_id = ?
  AND (? IS NULL OR vs.vaccine_id = ?);
```

```sql
SELECT b.id, b.batch_no, v.vaccine_name, b.production_date, b.expiry_date,
```

#### F-STOCK-006: 确认调拨

**功能描述：** 执行批次调拨操作，扣减调出位置库存，增加调入位置库存。

**输入参数：**
- 调拨单ID（必填）
- 医生ID（从会话中获取）

**输出结果：**
- 调拨成功：返回调拨结果
- 调拨失败：返回失败原因

**映射API：** POST /api/stock/transfer/confirm

**调拨逻辑：**
> **并发控制：** 使用 hospital_vaccine_summary.version 乐观锁（SRD 10.4）

```sql
-- 开启事务
BEGIN;

-- 乐观锁校验并扣减调出方汇总库存
UPDATE hospital_vaccine_summary
SET available_stock = available_stock - ?,
    version = version + 1
WHERE hospital_id = ? AND vaccine_id = ? AND version = ?;
-- 若影响行数为0，表示并发冲突，返回错误码 4093

-- 扣减调出位置库存
UPDATE hospital_vaccine_stock
SET available_stock = available_stock - ?
WHERE batch_id = ? AND available_stock >= ?;

-- 增加调入位置库存（如无则插入）
INSERT INTO hospital_vaccine_stock (hospital_id, batch_id, available_stock, locked_stock)
VALUES (?, ?, ?, 0)
ON DUPLICATE KEY UPDATE available_stock = available_stock + ?;

-- 更新调入方汇总库存
UPDATE hospital_vaccine_summary
SET total_stock = total_stock + ?,
    available_stock = available_stock + ?,
    version = version + 1
WHERE hospital_id = ? AND vaccine_id = ?;

-- 记录调拨日志
INSERT INTO stock_transfer_log (transfer_no, batch_id, from_type, from_id, to_type, to_id, quantity, operator_id, transfer_time, remark)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, NOW(), ?);

-- 提交事务
COMMIT;
```

#### F-STOCK-008: 销毁批次

**功能描述：** 销毁过期或损坏的批次，支持部分销毁和整批销毁。

**输入参数：**
- 医生ID（从会话中获取）
- 批次ID（必填）
- 销毁数量（必填）
- 销毁原因（必填）
- 备注（选填）

**输出结果：**
- 销毁成功：返回销毁记录ID
- 销毁失败：返回失败原因

**映射API：** POST /api/stock/batch/dispose

**销毁逻辑：**

**部分销毁逻辑：**
  当销毁数量 < 批次当前可用库存时（部分销毁）：
  - 仅扣减 quantity 字段：UPDATE vaccine_batch SET quantity = quantity - #{destroyQty} WHERE batch_id = #{batchId}
  - 不改变 status（批次仍为在库状态 status=1）
  - 记录销毁日志（stock_disposal_log）

**整批销毁逻辑：**
  当销毁数量 = 批次当前可用库存时（整批销毁）：
  - 扣减 quantity 并改变 status：UPDATE vaccine_batch SET quantity = 0, status = 3 WHERE batch_id = #{batchId}
  - 记录销毁日志

```sql
-- 开启事务
BEGIN;

-- 判断是否为整批销毁：销毁数量 = 批次当前可用库存
-- 部分销毁：仅扣减库存，不改变批次状态
UPDATE hospital_vaccine_stock
SET available_stock = available_stock - ?,
    locked_stock = CASE WHEN ? >= available_stock THEN 0 ELSE locked_stock END
WHERE batch_id = ? AND available_stock >= ?;

-- 整批销毁时更新批次状态为已销毁
UPDATE vaccine_batch
SET status = 3
WHERE id = ? AND ? >= (SELECT available_stock FROM hospital_vaccine_stock WHERE batch_id = ?);

-- 记录销毁日志（dispose_no由应用层生成，格式：DS+yyyyMMdd+4位序号）
INSERT INTO batch_dispose_log (dispose_no, batch_id, dispose_quantity, dispose_reason, operator_id)
VALUES (?, ?, ?, ?, ?);

-- 更新库存汇总（规则19：销毁操作后自动更新汇总）
UPDATE hospital_vaccine_summary vs
SET total_stock = (
      SELECT COALESCE(SUM(s.available_stock + s.locked_stock), 0)
      FROM hospital_vaccine_stock s
      WHERE s.hospital_id = vs.hospital_id AND s.batch_id IN (
        SELECT id FROM vaccine_batch WHERE vaccine_id = vs.vaccine_id
      )
    ),
    available_stock = (
      SELECT COALESCE(SUM(s.available_stock), 0)
      FROM hospital_vaccine_stock s
      WHERE s.hospital_id = vs.hospital_id AND s.batch_id IN (
        SELECT id FROM vaccine_batch WHERE vaccine_id = vs.vaccine_id
      )
    )
WHERE vs.hospital_id = ?;

-- 提交事务
COMMIT;
```

**规则说明：**
1. 部分销毁：仅扣减库存，批次状态不变
2. 整批销毁：销毁后批次状态更新为"已销毁"（status=3），锁定库存清零
3. 销毁原因必填
4. 需记录销毁日志

#### F-STOCK-009: 查询批次预警

**功能描述：** 查询触发预警的批次列表。

**输入参数：**
- 预警类型（可选，枚举值：ALL/LOW_STOCK/EXPIRY_SOON/EXPIRED）
- 分页参数：页码、每页数量

**输出结果：**
- 预警批次列表：
  - 批次ID
  - 批次号
  - 疫苗名称
  - 预警类型
  - 预警值
  - 预警时间
  - 是否已处理

**映射API：** GET /api/stock/alert/list?alertType={alertType}&page={page}&size={size}

**预警触发规则：**
> **定义来源：** SRD 7.4

1. 低库存预警（LOW_STOCK）：`remaining_ratio = (available_stock / (available_stock + locked_stock)) * 100`，当 remaining_ratio < 20% 时触发
2. 临期预警（EXPIRY_SOON）：expiry_date - warning_days < NOW()，标记批次 status=1（临期）
3. 过期预警（EXPIRED）：expiry_date < NOW()，标记批次 status=2（过期），必须销毁

```
|  - 对于临期预警：优先使用该批次                              |
|  - 对于过期预警：销毁该批次                                  |
|  - 处理后标记预警已处理                                      |
+-------------------------------------------------------------+
```

## 5. 业务规则

### 5.1 库存查询规则

#### 规则0：FEFO批次分配规则
> **定义来源：** SRD 7.2

- 规则描述：库存分配采用 FEFO（First Expire First Out）策略，优先分配即将过期的批次
- 执行逻辑：
  ```sql
  SELECT b.*, s.available_stock
  FROM vaccine_batch b
  JOIN hospital_vaccine_stock s ON b.id = s.batch_id
  WHERE b.vaccine_id = ? AND s.hospital_id = ?
        AND b.status = 0 AND s.available_stock > 0
        AND b.expiry_date > NOW()
  ORDER BY b.expiry_date ASC LIMIT 1
  FOR UPDATE;
  ```
- 说明：
  - 只分配状态为正常（status=0）的批次
  - 只分配有可用库存的批次
  - 只分配未过期的批次
  - 使用 `FOR UPDATE` 行级锁防止并发分配冲突
  - 按有效期升序排列，优先分配最早过期的批次

#### 规则1：库存汇总计算规则
- 规则描述：库存汇总按疫苗维度计算，汇总该疫苗所有批次的库存
- 执行逻辑：
  ```sql
  SELECT vaccine_id, SUM(available_stock) AS total_available, SUM(locked_stock) AS total_locked
  FROM hospital_vaccine_stock
  WHERE hospital_id = ?
  GROUP BY vaccine_id;
  ```
- 计算规则：
  - 总库存 = SUM(available_stock + locked_stock)
  - 可用库存 = SUM(available_stock)
  - 锁定库存 = SUM(locked_stock)
  - 剩余率 = (可用库存 / 总库存）x 100%
  - 使用率 = (锁定库存 / 总库存）x 100%

#### 规则2：批次库存查询规则
- 规则描述：查询批次库存时，必须同时查询可用库存和锁定库存
- 执行逻辑：
  ```sql
  SELECT available_stock, locked_stock
  FROM hospital_vaccine_stock
  WHERE batch_id = ? AND hospital_id = ?;
  ```
- 计算规则：
  - 总库存 = available_stock + locked_stock
  - 剩余率 = (available_stock / 总库存）x 100%

### 5.2 库存调拨规则

#### 规则3：调拨位置不能相同规则
- 规则描述：调出位置和调入位置不能相同
- 执行逻辑：`from_type != to_type OR from_id != to_id`
- 失败提示返回：`调出位置和调入位置不能相同`

#### 规则4：调拨库存充足规则
- 规则描述：调出位置的库存必须充足
- 执行逻辑：
  ```sql
  SELECT available_stock FROM hospital_vaccine_stock
  WHERE batch_id = ? AND hospital_id = ?;
  ```
  结果必须大于等于调拨数量
- 失败提示返回：`调出位置库存不足，无法调拨`

#### 规则5：调拨库存扣减规则
- 规则描述：调拨时扣减调出位置库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - ?
  WHERE batch_id = ? AND hospital_id = ? AND available_stock >= ?;
  ```

#### 规则6：调拨库存增加规则
- 规则描述：调拨时增加调入位置库存
- 执行逻辑：
  ```sql
  INSERT INTO hospital_vaccine_stock (hospital_id, batch_id, available_stock, locked_stock)
  VALUES (?, ?, ?, 0)
  ON DUPLICATE KEY UPDATE available_stock = available_stock + ?;
  ```

#### 规则7：调拨日志记录规则
- 规则描述：调拨操作必须记录日志
- 执行逻辑：
  ```sql
  INSERT INTO stock_transfer_log (transfer_no, batch_id, from_type, from_id, to_type, to_id, quantity, operator_id, transfer_time, remark)
  VALUES (?, ?, ?, ?, ?, ?, ?, ?, NOW(), ?);
  ```

### 5.3 批次销毁规则

#### 规则8：销毁批次状态规则
- 规则描述：只能销毁正常、临期、过期状态的批次
- 执行逻辑：`vaccine_batch.status IN (0, 1, 2)`
- 失败提示返回：`该批次已销毁，无法重复销毁`

#### 规则9：销毁数量校验
- 规则描述：销毁数量不能超过批次总库存
- 执行逻辑：销毁数量 <= (available_stock + locked_stock)
- 失败提示返回：`销毁数量不能超过批次总库存`

#### 规则10：销毁原因必填规则
- 规则描述：销毁原因必须填写
- 执行逻辑：dispose_reason IS NOT NULL AND dispose_reason != ''
- 失败提示返回：`请填写销毁原因`

#### 规则11：销毁库存扣减规则
- 规则描述：销毁时扣减批次库存，整批销毁时清空锁定库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - ?,
      locked_stock = CASE WHEN ? >= available_stock THEN 0 ELSE locked_stock END
  WHERE batch_id = ? AND available_stock >= ?;
  ```

#### 规则12：销毁批次状态更新规则
- 规则描述：整批销毁后批次状态更新为"已销毁"（status=3），部分销毁不改变状态
- 执行逻辑：
  ```sql
  -- 整批销毁：更新批次状态
  UPDATE vaccine_batch
  SET status = 3
  WHERE id = ? AND ? >= (SELECT available_stock FROM hospital_vaccine_stock WHERE batch_id = ?);

  -- 部分销毁：不改变批次状态，仅扣减库存
  ```

### 5.4 库存预警规则
> **定义来源：** SRD 7.4

#### 规则13：低库存预警规则（LOW_STOCK）
- 规则描述：剩余率低于20%时触发低库存预警
- 计算公式：`remaining_ratio = (available_stock / (available_stock + locked_stock)) * 100`
- 触发条件：`remaining_ratio < 20%`
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, available_stock, locked_stock,
         (available_stock / (available_stock + locked_stock)) * 100 AS remaining_ratio
  FROM hospital_vaccine_stock
  WHERE (available_stock / (available_stock + locked_stock)) * 100 < 20;
  ```
- 处理动作：记录预警日志，自动调用供应商接口补货（二期功能：一期仅记录预警日志和推送站内通知，供应商接口对接在二期实现），推送系统消息给库存医生（SRD 5.4）

#### 规则14：临期预警规则（EXPIRY_SOON）
- 规则描述：有效期小于预警天数时触发临期预警
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, expiry_date, warning_days
  FROM vaccine_batch
  WHERE expiry_date - warning_days < NOW()
    AND status = 0;
  ```
- 处理动作：标记批次状态为临期（status=1），记录预警日志，推送系统消息给库存医生（SRD 5.4）

#### 规则15：过期预警规则（EXPIRED）
- 规则描述：有效期小于当前时间时触发过期预警
- 执行逻辑：
  ```sql
  SELECT batch_id, vaccine_id, expiry_date
  FROM vaccine_batch
  WHERE expiry_date < NOW()
    AND status IN (0, 1);
  ```

> 注：过期预警需同时检查 status=0（正常/入库）和 status=1（在库）的批次，
> 因为新入库的批次（status=0）也可能已临期。条件为 status IN (0, 1)。
> 其他模块引用此规则时请保持一致。

- 处理动作：标记批次状态为过期（status=2），记录预警日志，不可继续使用，**必须销毁**

#### 规则16：预警标记处理规则
- 规则描述：标记预警已处理时，记录处理人和处理时间
- 执行逻辑：
  ```sql
  UPDATE stock_alert_log
  SET is_handled = 1,
      handled_by = ?,
      handled_time = NOW(),
      handle_remark = ?
  WHERE id = ?;
  ```

### 5.5 批次状态流转规则

#### 规则17：批次状态流转规则
> **定义来源：** SRD A.6 批次状态枚举

- 规则描述：批次状态只能按特定顺序流转
- 允许流转：
  - 正常（0）-> 临期（1）：定时任务检测临期
  - 正常（0）-> 已销毁（3）：手动销毁
  - 正常（0）-> 过期（2）：定时任务检测过期
  - 临期（1）-> 过期（2）：定时任务检测过期
  - 临期（1）-> 已销毁（3）：手动销毁
  - 过期（2）-> 已销毁（3）：手动销毁
- 禁止流转：
  - 已销毁（3）-> 其他状态（终态）

#### 规则18：批次自动过期规则
- 规则描述：批次过期后自动更新状态为"过期"（status=2）
- 执行逻辑：
  ```sql
  UPDATE vaccine_batch
  SET status = 2
  WHERE expiry_date < NOW() AND status IN (0, 1);
  ```

### 5.6 库存汇总维护规则

#### 规则19：库存汇总自动更新规则
- 规则描述：当批次库存变化时，自动更新库存汇总表
- 触发时机：
  - 调拨操作后
  - 销毁操作后
  - 库存锁定后
  - 库存扣减后
- 执行逻辑：
  ```sql
  -- 更新库存汇总
  UPDATE hospital_vaccine_summary vs
  SET total_stock = (
        SELECT COALESCE(SUM(s.available_stock + s.locked_stock), 0)
        FROM hospital_vaccine_stock s
        WHERE s.hospital_id = vs.hospital_id AND s.batch_id IN (
          SELECT id FROM vaccine_batch WHERE vaccine_id = vs.vaccine_id
        )
      ),
      available_stock = (
        SELECT COALESCE(SUM(s.available_stock), 0)
        FROM hospital_vaccine_stock s
        WHERE s.hospital_id = vs.hospital_id AND s.batch_id IN (
          SELECT id FROM vaccine_batch WHERE vaccine_id = vs.vaccine_id
        )
      )
  WHERE vs.hospital_id = ?;
  ```

### 5.7 库存操作规则
> **定义来源：** SRD 7.3

#### 规则20：登记锁定库存（预约登记时调用）
- 规则描述：预约登记时锁定批次库存，将可用库存转为锁定库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock + 1
  WHERE batch_id = ? AND available_stock > 0;
  ```
- 说明：通过 `available_stock > 0` 条件保证不超卖

#### 规则21：接种扣减库存（完成接种时调用）
- 规则描述：完成接种后扣减库存，同时减少可用库存和锁定库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - 1,
      locked_stock = locked_stock - 1
  WHERE batch_id = ? AND available_stock > 0;
  ```
- 说明：通过 `available_stock > 0` 条件保证不超卖

#### 规则22：取消预约释放库存（取消预约时调用）
- 规则描述：取消预约后释放锁定的库存，将锁定库存转为可用库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET locked_stock = locked_stock - 1
  WHERE batch_id = ? AND locked_stock > 0;
  ```
- 说明：通过 `locked_stock > 0` 条件保证不超释放

### 5.8 并发控制规则
> **定义来源：** SRD 10.4

#### 规则23：登记并发控制
- 规则描述：预约登记时使用行级锁防止并发分配同一批次库存
- 控制方式：`SELECT ... FOR UPDATE` 对批次行加悲观锁
- 配合 FEFO 分配规则使用（见规则0）

#### 规则24：接种并发控制
- 规则描述：接种扣减库存时使用条件更新防止并发超卖
- 控制方式：`UPDATE ... WHERE available_stock > 0` + `FOR UPDATE`
- 影响行数为0时表示并发冲突，返回错误码 4093

#### 规则25：调拨并发控制
- 规则描述：库存调拨时使用乐观锁防止并发调拨导致数据不一致
- 控制方式：基于 `hospital_vaccine_summary.version` 字段的乐观锁
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_summary
  SET available_stock = available_stock - ?,
      version = version + 1
  WHERE hospital_id = ? AND vaccine_id = ? AND version = ?;
  ```
- 说明：当 `version` 不匹配时（影响行数为0），表示存在并发修改，返回错误码 4093

### 5.9 通知规则
> **定义来源：** SRD 5.4

#### 规则26：库存预警通知
- 规则描述：库存预警触发时，系统自动推送系统消息给库存管理医生
- 触发场景：
  - 低库存预警（LOW_STOCK）触发时
  - 临期预警（EXPIRY_SOON）触发时
  - 过期预警（EXPIRED）触发时
- 通知方式：系统消息（站内信）
- 接收人：DOCTOR_STOCK 角色的医生

### 5.10 库存锁定超时释放规则

#### 规则27：库存锁定超时释放
- 规则描述：库存锁定后，如超过 2 小时未被确认扣减（接种完成），系统自动释放锁定的库存
- 释放逻辑：locked_stock - 1，同时通知相关登记医生
- 超时释放由定时任务（每小时执行一次）扫描超时的锁定记录
- 执行逻辑：
  ```sql
  -- 定时任务每小时执行一次，扫描超过2小时未确认的锁定记录
  UPDATE hospital_vaccine_stock s
  SET locked_stock = locked_stock - 1,
      available_stock = available_stock + 1
  WHERE s.batch_id IN (
    SELECT lr.batch_id FROM stock_lock_record lr
    WHERE lr.status = 0
      AND lr.lock_time < DATE_SUB(NOW(), INTERVAL 2 HOUR)
  );
  ```
- 说明：
  - 超时阈值为 2 小时（可配置）
  - 释放时同步通知相关登记医生
  - 释放记录写入日志表

## 8. 异常场景

### 8.1 业务异常

> **错误码范围：** 库存模块所有业务错误码使用 **4001-4099** 范围，其中 4001-4008 为业务校验类错误，4091-4099 为系统级错误。

#### E-STOCK-001：调拨位置相同

**场景描述：** 调出位置和调入位置相同

**触发条件：** from_type == to_type AND from_id == to_id

**错误码：** 4001
**错误消息：** `调出位置和调入位置不能相同，请重新选择`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导医生重新选择调入位置

---

#### E-STOCK-002：调出位置库存不足

**场景描述：** 调出位置的库存不足以调拨

**触发条件：**
```sql
SELECT available_stock FROM hospital_vaccine_stock
WHERE batch_id = ? AND hospital_id = ?;
```
返回结果 < 调拨数量

**错误码：** 4002
**错误消息：** `调出位置库存不足，可用库存：{available_stock}，调拨数量：{quantity}，请减少调拨数量`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示库存信息
- 引导医生减少调拨数量
- 或引导医生选择其他批次

---

#### E-STOCK-003：调拨失败

**场景描述：** 调拨操作执行失败

**触发条件：** 调拨SQL执行失败

**错误码：** 4091
**错误消息：** `调拨失败，请重试或联系管理员`
**HTTP状态码：** 500 Internal Server Error

**处理建议：**
- 显示错误消息
- 引导医生重试
- 记录错误日志

---

#### E-STOCK-004：批次已销毁

**场景描述：** 批次已销毁，无法进行调拨或销毁

**触发条件：** vaccine_batch.status = 3

**错误码：** 4003
**错误消息：** `该批次已销毁，无法操作，请选择其他批次`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导医生选择其他批次

---

#### E-STOCK-005：销毁数量超限

**场景描述：** 销毁数量超过批次总库存

**触发条件：** 销毁数量 > (available_stock + locked_stock)

**错误码：** 4004
**错误消息：** `销毁数量不能超过批次总库存，总库存：{total_stock}，销毁数量：{quantity}`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示批次库存信息
- 引导医生输入正确的销毁数量

---

#### E-STOCK-006：销毁原因未填写

**场景描述：** 销毁原因未填写

**触发条件：** dispose_reason IS NULL OR dispose_reason = ''

**错误码：** 4005
**错误消息：** `请填写销毁原因`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导医生填写销毁原因

---

#### E-STOCK-007：批次不存在

**场景描述：** 批次不存在

**触发条件：** vaccine_batch表中不存在该批次ID

**错误码：** 4006
**错误消息：** `批次不存在，请检查批次号`
**HTTP状态码：** 404 Not Found

**处理建议：**
- 显示错误消息
- 引导医生检查批次号

---

### 8.2 系统异常

#### E-STOCK-101：数据库连接异常

**场景描述：** 数据库连接失败或超时

**错误码：** 4092
**错误消息：** `系统繁忙，请稍后重试`
**HTTP状态码：** 500 Internal Server Error

**处理建议：**
- 显示友好错误消息
- 自动重试机制（最多3次）
- 记录错误日志，发送告警给运维

---

#### E-STOCK-102：并发冲突

**场景描述：** 多个医生同时操作同一批次，导致并发冲突

**错误码：** 4093
**错误消息：** `系统繁忙，请稍后重试`
**HTTP状态码：** 409 Conflict

**处理建议：**
- 显示友好错误消息
- 自动重试机制（最多3次）
- 使用数据库乐观锁或悲观锁解决并发

---

#### E-STOCK-103：参数验证失败

**场景描述：** 请求参数格式不正确或缺少必填参数

**错误码：** 4007
**错误消息：** `请求参数不正确：{field_name}不能为空/格式不正确`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示具体字段错误
- 引导医生修正后重试
- 前端增加参数校验

---

#### E-STOCK-104：Session过期

**场景描述：** 医生Session过期，Token无效

**错误码：** 4008
**错误消息：** `登录已过期，请重新登录`
**HTTP状态码：** 401 Unauthorized

**处理建议：**
- 清除本地Token
- 跳转到登录页
- 引导医生重新登录

---

#### E-STOCK-105：未登录异常

**场景描述：** 用户未登录即访问库存模块接口

**错误码：** 401
**HTTP状态码：** 401 Unauthorized

**处理策略：** 跳转至登录页面

---

#### E-STOCK-106：无权限异常

**场景描述：** 用户已登录但无对应功能权限

**错误码：** 403
**HTTP状态码：** 403 Forbidden

**处理策略：** 返回权限错误提示

---

#### E-STOCK-107：关联服务不可用

**场景描述：** 调用关联服务（如通知服务）失败

**触发条件：** 调用关联服务（如通知服务）失败

**错误码：** 4051
**HTTP状态码：** 500 Internal Server Error

**处理策略：** 记录失败日志，主操作不受影响

---

### 8.3 异常处理流程

```
异常发生
  |
  记录错误日志（含堆栈信息、请求参数、医生信息）
  |
  判断异常类型
  |
  |- 业务异常（E-STOCK-001~007）
  |   |
  |   返回友好错误消息给医生
  |   显示处理建议
  |   记录业务异常日志
  |
  |- 权限异常（E-STOCK-105~106）
  |   |
  |   未登录：跳转至登录页面
  |   无权限：返回权限错误提示
  |   记录权限异常日志
  |
  |- 关联服务异常（E-STOCK-107）
  |   |
  |   记录失败日志
  |   主操作不受影响
  |   后续重试或人工处理
  |
  |- 系统异常（E-STOCK-101~104，错误码 4091~4094）
  |   |
  |   返回系统错误提示
  |   发送告警给运维
  |   记录系统异常日志
  |
  |- 未知异常
  |   |
  |   返回通用错误提示
  |   发送紧急告警给运维
  |   记录未知异常日志
  |
  事务回滚（如有）
  |
  返回统一响应格式
```
