## 1. 模块概述

### 1.1 模块定位

接种模块是疫苗管理系统的核心模块之一，负责疫苗接种的实际执行环节。该模块是疫苗接种流程的第5个环节（签到→预检→登记→接种→留观），连接登记环节和留观环节。

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 接种执行 | 疫苗目录管理（属于疫苗模块） |
| 接种部位选择 | 预检评估（属于预检模块） |
| 注射号生成 | 登记批次分配（属于登记模块） |
| 库存扣减 | 留观管理（属于留观模块） |
| 接种记录登记 | 儿童档案管理（属于用户模块） |
| 接种记录查询 | 医生排班（属于排班模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| DOCTOR_VACCINATE | 接种医生 | 查看待接种队列、执行接种、记录接种信息、查询接种记录 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 查看接种统计、接种记录审核 |

### 1.4 核心业务价值

- **规范接种流程**：标准化的接种操作流程，确保接种安全
- **数据可追溯**：完整的接种记录，支持质量问题追溯和统计分析
- **库存准确管理**：接种时准确扣减库存，避免库存误差
- **注射号唯一**：生成唯一的注射号，便于留观和查询
- **接种记录完整**：记录接种的详细信息，包括接种部位、批次、时间等

### 1.5 业务场景

**场景1：家长完成登记后到接种窗口**
```
家长到接种窗口
  ↓
接种医生查询待接种队列
  ↓
找到对应预约（排队号）
  ↓
核实儿童信息和预约信息
  ↓
选择接种部位
  ↓
执行疫苗接种
  ↓
生成唯一注射号
  ↓
扣减批次库存
  ↓
记录接种信息
  ↓
通知家长开始留观
  ↓
家长带孩子进入留观室
```

### 2.2 功能详情

#### F-VACCINATE-001: 查看待接种队列

**功能描述：** 接种医生查询已登记但尚未接种的预约列表。

**输入参数：**
- 医生ID（从会话中获取）
- 预约日期（可选，默认当天）

**输出结果：**
- 预约列表：
  - 预约ID
  - 排队号
  - 儿童姓名
  - 登记时间
  - 批次号
  - 批次有效期
  - 接种状态

**映射API：** GET /api/vaccinate/queue?date={date}

**查询逻辑：**
```sql
SELECT a.id, rq.queue_number, cp.name AS child_name, rq.created_at, vb.batch_no, vb.expiry_date
FROM appointment a
JOIN register_queue rq ON a.id = rq.appointment_id
JOIN child_profile cp ON a.child_id = cp.id
JOIN vaccine_batch vb ON a.batch_id = vb.id
WHERE a.appointment_date = ?
  AND a.status = 8
ORDER BY rq.created_at ASC;
```

#### F-VACCINATE-003: 核实信息

**功能描述：** 接种医生核实儿童信息、预约信息和批次信息，确保信息准确无误。

**输入参数：**
- 预约ID（必填）
- 儿童信息确认（必填）
- 预约信息确认（必填）
- 批次信息确认（必填）

**输出结果：**
- 核实成功：返回确认信息
- 核实失败：返回失败原因

**映射API：** POST /api/vaccinate/verify

**核实项目：**
1. 儿童姓名是否匹配
2. 儿童出生日期是否匹配
3. 预约疫苗是否匹配
4. 登记批次号是否匹配
5. 批次有效期是否有效

-（无参数，前端选择后提交）

**输出结果：**

#### F-VACCINATE-005: 执行接种

**功能描述：** 接种医生执行疫苗接种操作（含注射号生成、库存扣减、记录保存、状态更新），为原子操作。

**输入参数：**
```json
{
  "appointmentId": 123,
  "injectionSite": "左上臂"
}
```

**输出结果（SRD 9.5）：**
```json
{
  "code": 200,
  "message": "接种成功",
  "data": {
    "appointmentId": 123,
    "injectionId": "INJ202604050001",
    "injectionSite": "左上臂",
    "batchNo": "HBV202401001",
    "status": 10,
    "nextGuide": "请在留观室观察30分钟"
  }
}
```

**映射API：** POST /api/vaccinate/execute

**权限要求：** `vaccinate.execute`

**执行流程（事务内完成）：**

**步骤1：生成注射号**
```sql
SELECT MAX(CAST(SUBSTRING(injection_id, 13, 4) AS UNSIGNED)) AS max_seq
FROM vaccination_record
WHERE DATE(vaccinate_time) = ?;
new_injection_id = 'INJ' + DATE_FORMAT(CURDATE(), '%Y%m%d') + LPAD(CAST(max_seq + 1 AS CHAR), 4, '0');
```

**步骤2：扣减库存（SRD 7.3，同时扣减 available 和 locked）**
```sql
SELECT id FROM hospital_vaccine_stock WHERE batch_id = ? FOR UPDATE;
UPDATE hospital_vaccine_stock
SET available_stock = available_stock - 1,
    locked_stock = locked_stock - 1
WHERE batch_id = ? AND available_stock > 0;
```

**步骤3：保存接种记录（SRD 8.3）**
```sql
INSERT INTO vaccination_record (appointment_id, child_id, vaccine_id, batch_id, batch_no, doctor_id, injection_id, injection_site, vaccinate_time, hospital_id, created_at)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, NOW(), ?, NOW());
```

**步骤4：更新预约状态**
```sql
UPDATE appointment
SET status = 10, current_window = 'OBSERVE', vaccinate_time = NOW()
WHERE id = ?;
```

**事务控制：** 以上4个步骤在同一事务内执行，任一步骤失败则全部回滚。

**并发控制（SRD 10.4）：** 使用 `FOR UPDATE` 行锁 + `WHERE available_stock > 0` 条件校验防止超卖。

#### F-VACCINATE-006: 查询接种记录

**功能描述：** 查询接种医生自己执行的接种记录列表。

**权限要求：** `record.view.own`

**输入参数：**
- 医生ID（从会话中获取）
- 日期范围（可选）
- 分页参数：页码、每页数量

**输出结果：**
- 接种记录列表：
  - 注射号
  - 儿童姓名
  - 疫苗名称
  - 接种部位
  - 批次号
  - 接种时间

> **说明：** 用户端接种记录查询返回精简字段（儿童姓名、疫苗名称、接种日期、接种部位），等同于 SRD 中的 `record` 视图。`record` 是基于 `vaccination_record` 的数据库 VIEW，仅暴露面向用户的字段，不存储独立数据，与 `vaccination_record` 为 1:1 关系。

**映射API：** GET /api/vaccinate/record/list?startDate={startDate}&endDate={endDate}&page={page}&size={size}

**查询逻辑：**
```sql
SELECT vr.injection_id, cp.name AS child_name, v.vaccine_name, vr.injection_site, vr.batch_no, vr.vaccinate_time
FROM vaccination_record vr
JOIN appointment a ON vr.appointment_id = a.id
JOIN child_profile cp ON a.child_id = cp.id
JOIN vaccine_batch vb ON vr.batch_id = vb.id
JOIN vaccine v ON vb.vaccine_id = v.id
WHERE vr.doctor_id = ?
  AND (? IS NULL OR DATE(vr.vaccinate_time) >= ?)
  AND (? IS NULL OR DATE(vr.vaccinate_time) <= ?)
ORDER BY vr.vaccinate_time DESC
LIMIT ? OFFSET ?;
```

## 5. 业务规则

### 5.1 接种业务规则

#### 规则1：预约状态校验
- 规则描述：只有状态为"已登记"（status=8）的预约可以接种
- 执行逻辑：`appointment.status = 8`
- 失败提示返回：`该预约状态不允许接种，当前状态：{status_text}`

#### 规则2：批次库存充足校验
- 规则描述：批次可用库存必须大于 0 才能接种
- 执行逻辑：
  ```sql
  SELECT available_stock
  FROM hospital_vaccine_stock
  WHERE batch_id = ?;
  ```
  available_stock > 0

- 失败提示返回：`批次库存不足，无法接种`

#### 规则3：批次有效期校验
- 规则描述：批次有效期必须大于当前时间
- 执行逻辑：`vaccine_batch.expiry_date > NOW()`
- 失败提示返回：`该批次已过期，无法接种`

#### 规则4：接种部位必填校验
- 规则描述：接种部位必须选择
- 执行逻辑：injection_site IS NOT NULL AND injection_site != ''
- 失败提示返回：`请选择接种部位`

#### 规则5：注射号唯一性校验
- 规则描述：注射号必须唯一
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM vaccination_record WHERE injection_id = ?;
  ```
  结果必须为0
- 失败提示返回：`注射号生成失败，请重试`

#### 规则6：库存扣减规则
- 规则描述：接种时扣减批次库存，同时减去可用库存和锁定库存
- 执行逻辑：
  ```sql
  UPDATE hospital_vaccine_stock
  SET available_stock = available_stock - 1,
      locked_stock = locked_stock - 1
  WHERE batch_id = ?
    AND available_stock > 0;
  ```

#### 规则7：接种记录保存规则
- 规则描述：接种成功后保存接种记录到数据库
- 执行逻辑：
  ```sql
  INSERT INTO vaccination_record (appointment_id, child_id, vaccine_id, batch_id, batch_no, doctor_id, injection_id, injection_site, vaccinate_time, hospital_id, created_at)
  VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, NOW(), ?, NOW());
  ```

#### 规则8：预约状态更新规则
- 规则描述：接种成功后更新预约状态为"留观中"（status=10），同时记录接种时间和当前窗口
- 执行逻辑：
  ```sql
  UPDATE appointment
  SET status = 10,
      current_window = 'OBSERVE',
      vaccinate_time = NOW()
  WHERE id = ?;
  ```

#### 规则9：接种医生权限校验
- 规则描述：只有接种医生可以执行接种操作
- 执行逻辑：用户角色包含`DOCTOR_VACCINATE`
- 失败提示返回：`无权限执行接种操作`

#### 规则10：接种记录查询权限校验
- 规则描述：接种医生只能查询自己由执行的接种记录
- 执行逻辑：`vaccination_record.doctor_id = current_doctor_id`
- 失败提示返回：`无权查看该接种记录`

### 5.2 接种部位选择规则

#### 规则11：上臂接种优先规则
- 规则描述：大多数疫苗优先选择上臂接种
- 说明：上臂三角肌是大多数疫苗的推荐接种部位，肌肉丰富，疼痛较轻

#### 规则12：臀部接种条件规则
- 规则描述：以下情况可选择臀部接种
- 条件：
  - 儿童年龄较大（建议3岁以上）
  - 需要接种较大剂量的疫苗
  - 上臂肌肉量不足

#### 规则13：左右侧交替规则
- 规则描述：多次接种时左右侧交替，避免同一侧重复
- 说明：查看儿童历史接种记录，优先选择与上次不同的侧

### 5.3 状态流转规则

#### 接种状态流转

```
status=8（已登记）
    ↓ 接种医生接种
status=10（留观中）
    ↓ 留观医生确认留观结束
status=2（已完成）

异常分支：
status=10（留观中）→有不良反应→记录不良反应
```

#### 状态流转约束

| 当前状态 | 可流转状态 | 触发条件 | 流转角色 |
|----------|------------|----------|----------|
| 8（已登记） | 10（留观中） | 接种完成 | DOCTOR_VACCINATE |
| 10（留观中） | 2（已完成） | 留观结束 | DOCTOR_OBSERVE |

> 注：接种完成后 current_window 设为 'OBSERVE'（而非 'VACCINATE'），指引用户前往留观室。此设置需与 PRD-FLOW 的窗口指引规则保持一致。

#### 规则14：库存不足处理
- 规则描述：正常情况下库存已在登记环节锁定，接种时仅确认扣减。但如果锁定期间库存被异常释放（如超时释放），接种时可能出现库存不足
- 处理方式：
  1. 返回错误提示"库存异常，请联系管理员"
  2. 医生手动触发库存重新锁定流程
  3. 如无法锁定，通知管理员介入处理

#### 规则15：接种失败处理
- 规则描述：接种执行过程中如发生异常（如注射器故障、疫苗瓶破裂等）
- 处理方式：
  1. 如未完成注射，本次接种不计入接种记录，可重新执行接种流程
  2. 如已完成部分注射，记录为"接种异常"，创建异常记录到 observe_record 表（由PRD-FLOW管理），记录异常类型为接种失败
  3. 医生手动记录异常原因到 observe_record.abnormal_description 字段
  4. 系统不扣减库存（或根据实际消耗扣减）
  5. 用户进入留观流程进行异常观察

#### 规则16：不良反应关联
- 规则描述：不良反应记录通过 appointment_id 和 injection_id 与接种记录关联（基于 observe_record 表）
- 发生不良反应时：
  1. 通过 observe_record.injection_id 关联到接种记录
  2. 创建不良反应详细记录（由PRD-FLOW管理）
  3. 留观时间自动延长（由PRD-FLOW管理）

### 7.5 权限校验流程

```
用户请求
  ↓
解析Token获取用户ID
  ↓
查询用户角色：sys_user_role WHERE user_id = ?
  ↓
查询角色权限：sys_role_permission WHERE role_id IN (...)
  ↓
判断请求接口是否在权限列表
  ↓
  ├─ 有权限 → 继续执行
  └─ 无权限 → 返回403 Forbidden
  ↓
数据访问权限校验
  ↓
  ├─ DOCTOR_VACCINATE类型 → WHERE doctor_id = current_doctor_id OR status = 8
  ├─ 管理员类型 → 无限制
  └─ 其他类型 → 返回403 Forbidden
  ↓
执行业务逻辑
  ↓
返回响应结果
```

## 8. 异常场景

### 8.1 业务异常

#### E-VACCINATE-001：预约状态异常

**场景描述：** 预约当前状态不允许接种操作

**触发条件：** appointment.status != 8

**错误码：** 3201
**错误消息：** `该预约状态不允许接种，当前状态：{status_text}`
**HTTP状态码：** 403 Forbidden

**处理建议：**
- 显示当前状态给医生
- 引导医生查看预约详情
- 只有状态为"已登记"的预约可以接种

---

#### E-VACCINATE-002：批次库存不足

**场景描述：** 批次库存不足，无法接种

**触发条件：**
```sql
SELECT available_stock
FROM hospital_vaccine_stock
WHERE batch_id = ?;
```
available_stock <= 0

**错误码：** 3202
**错误消息：** `批次库存不足，可用库存：{available_stock}，无法接种`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示批次库存信息
- 引导医生联系库存医生
- 引导医生更换批次（如有备用批次）

---

#### E-VACCINATE-003：批次已过期

### 8.3 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息、请求参数、医生信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-VACCINATE-001~010）
  │   ↓
  │   返回友好错误消息给医生
  │   显示处理建议
  │   记录业务异常日志
  │
  ├─ 系统异常（E-VACCINATE-101~104）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```

### 8.4 重试机制

**可重试的异常：**
- E-VACCINATE-005：注射号生成失败
- E-VACCINATE-006：库存扣减失败
- E-VACCINATE-007：接种记录保存失败
- E-VACCINATE-008：预约状态更新失败
- E-VACCINATE-101：数据库连接异常
- E-VACCINATE-102：并发冲突

**重试策略：**
- 最大重试次数：3次
- 重试间隔：1秒、2秒、4秒（指数退避）
- 超时时间：30秒

> 注：本PRD采用指数退避重试策略，优于SRD 10.4节定义的固定间隔100ms重试。固定间隔重试在高并发场景下可能导致重试风暴，指数退避可有效缓解。

**重试逻辑：**
```
重试次数 = 0
WHILE 重试次数 < 3
  尝试执行操作
  成功 → 返回结果
  失败且可重试 → 重试次数+1，等待后继续
  失败且不可重试 → 抛出异常
END WHILE
抛出异常（重试失败）
```
