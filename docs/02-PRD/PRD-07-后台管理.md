## 1. 模块概述

### 1.1 模块定位

后台管理模块是疫苗管理系统的管理核心模块，负责医院后台管理人员的各类管理操作。该模块涵盖医生排班、窗口管理、疫苗管理、公告管理、统计分析五个子模块，是医院业务配置、资源调配和数据统计分析的关键枢纽。

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 医生排班创建、修改、查询、删除 | 预约创建（属于预约模块） |
| 窗口配置、职能定义、容量调整、服务管理 | 接种执行（属于接种模块） |
| 疫苗目录管理（含增删改查、上下架操作） | 库存扣减（属于库存模块） |
| 公告发布、审批、查看、反馈 | 预检评估（属于预检模块） |
| 统计分析、数据报表、趋势图（含异常统计） | 留观管理（属于留观模块） |
| 角色权限管理、用户角色分配 | 疫苗接种记录管理（属于接种模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| SUPER_ADMIN | 系统管理员 | 系统维护、用户管理、公告审批/发布、统计分析、全局数据查看 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 医生排班（仅查看）、窗口管理、窗口服务管理、疫苗目录管理、分配角色权限、公告发布 |
| DOCTOR_SCHEDULE | 排班医生 | 医生排班（创建/修改/删除/查看）、公告查看 |

### 1.4 核心业务价值

- **资源优化配置**：通过排班管理和窗口管理，合理调配医院资源，提高服务效率
- **业务规则统一**：通过疫苗管理，统一配置疫苗规则，确保接种规范
- **信息及时传达**：通过公告管理，及时传达医院政策和通知
- **数据决策支持**：通过统计分析，提供多维度数据报表，辅助管理决策
- **权限精细管控**：通过角色权限管理，实现职责分离和权限隔离

## 3. 医生排班子模块（SCHEDULE）

### 3.1 子模块概述

医生排班子模块负责管理医生排班信息，包括排班创建、修改、查询、删除等操作。通过排班管理，合理安排医生工作时间，确保各窗口在开放时间内有医生值班，同时支持预约容量控制，避免过度预约。

### 3.2 子模块功能列表

#### F-ADMIN-001: 创建排班

**功能描述：** 创建医生排班记录，安排医生在指定窗口的值班时间。

**输入参数：**
- 医生ID（必填）
- 窗口ID（必填）
- 排班日期（必填，格式：YYYY-MM-DD）
- 开始时间（必填，格式：HH:mm:ss）
- 结束时间（必填，格式：HH:mm:ss）

**输出结果：**
- 排班记录ID
- 排班记录详情

**映射API：** POST /api/schedule

**业务规则：**
1. 医生必须存在且状态正常
2. 窗口必须存在且状态为开放
3. 排班日期必须为未来日期或当天
4. 开始时间必须早于结束时间
5. 排班时间必须与该医生其他排班无冲突
6. 排班时间必须在窗口开放时间内

---

#### F-ADMIN-002: 修改排班

**功能描述：** 修改已存在的医生排班记录。

**输入参数：**
- 排班记录ID（必填）
- 医生ID（必填）
- 窗口ID（必填）
- 排班日期（必填）
- 开始时间（必填）
- 结束时间（必填）

**输出结果：**
- 排班记录ID
- 排班记录详情

**映射API：** PUT /api/schedule/{id}

**业务规则：**
1. 排班记录必须存在
2. 修改后的排班时间必须与该医生其他排班无冲突
3. 排班日期已过且已有预约的排班不能修改时间

---

#### F-ADMIN-003: 查询排班

**功能描述：** 查询医生排班记录，支持多种筛选条件。

**输入参数：**
- 医生ID（选填）
- 窗口ID（选填）
- 排班日期（选填）
- 排班日期范围（选填，开始日期和结束日期）
- 分页参数：页码、每页数量

**输出结果：**
- 排班记录列表
- 总记录数
- 当前页信息

**映射API：** GET /api/schedule?doctorId={doctorId}&windowId={windowId}&date={date}&startDate={startDate}&endDate={endDate}&page={page}&pageSize={pageSize}

---

#### F-ADMIN-004: 删除排班

**功能描述：** 删除医生排班记录。

**输入参数：** 排班记录ID（必填）

**输出结果：**
- 删除成功确认信息

**映射API：** DELETE /api/schedule/{id}

**业务规则：**
1. 排班记录必须存在
2. 该排班日期下已有预约的排班不能删除
3. 删除后排班记录状态标记为已删除

---

#### F-ADMIN-005: 排班冲突检测

**功能描述：** 检测指定排班时间是否与该医生其他排班冲突。

**输入参数：**
- 医生ID（必填）
- 排班日期（必填）
- 开始时间（必填）
- 结束时间（必填）
- 排班记录ID（选填，用于排除当前记录）

**输出结果：**
- 是否冲突（true/false）
- 冲突详情（如有冲突）

**映射API：** POST /api/schedule/conflict

**业务规则：**
1. 查询该医生在指定日期的所有排班
2. 检查时间区间是否重叠
3. 返回冲突结果

### 3.5 业务规则

#### 规则1：医生状态校验
- 规则描述：医生必须存在且状态正常
- 执行逻辑：检查医生状态为正常

#### 规则2：窗口状态校验
- 规则描述：窗口必须存在且状态为开放
- 执行逻辑：检查窗口状态为开放

#### 规则3：排班日期有效性校验
- 规则描述：排班日期必须为未来日期或当天
- 执行逻辑：排班日期 >= 当天

#### 规则4：时间区间校验
- 规则描述：开始时间必须早于结束时间
- 执行逻辑：开始时间 < 结束时间

#### 规则5：窗口开放时间校验
- 规则描述：排班时间必须在窗口开放时间内
- 执行逻辑：排班时间 >= 窗口开放时间 AND 排班时间 <= 窗口关闭时间

#### 规则6：排班时间冲突校验
- 规则描述：排班时间必须与该医生其他排班无冲突
- 执行逻辑：该医生在排班日期的所有排班时间区间与当前排班时间区间无重叠

#### 规则7：排班唯一约束
- 规则描述：同一医生同一窗口同一日期不可重复排班
- 执行逻辑：(doctor_id, schedule_date, window_id) 唯一

#### 规则8：排班修改限制
- 规则描述：排班日期已过且已有预约的排班不能修改时间
- 执行逻辑：排班日期 >= 当天 OR 该排班下无预约记录

#### 规则9：排班删除限制
- 规则描述：该排班日期下已有预约的排班不能删除
- 执行逻辑：该排班下无预约记录

## 4. 窗口管理子模块（WINDOW）

### 4.1 子模块概述

窗口管理子模块负责管理医院窗口配置，包括窗口增删改查、窗口职能配置、窗口容量调整、窗口服务说明等操作。通过窗口管理，灵活配置医院各类窗口，满足不同业务场景需求。支持窗口动态管理（SRD 4.2），可随时新增、修改、删除窗口，调整职能类型和容量，删除时需确保无数据关联。

### 4.2 子模块功能列表

#### F-ADMIN-006: 新增窗口

**功能描述：** 新增窗口配置。

**输入参数：**
- 窗口编码（必填）
- 窗口名称（必填）
- 窗口描述（选填）

### 4.5 业务规则

#### 规则10：窗口编码唯一性
- 规则描述：窗口编码必须唯一
- 执行逻辑：窗口编码在窗口表中不存在

#### 规则11：窗口职能类型有效性
- 规则描述：窗口职能类型必须有效
- 执行逻辑：窗口职能类型在预定义类型列表中

#### 规则12：角色编码有效性
- 规则描述：分配的角色编码必须存在
- 执行逻辑：角色编码在角色表中存在

#### 规则13：容量有效性
- 规则描述：容量必须大于0
- 执行逻辑：容量 > 0

#### 规则14：时间区间有效性
- 规则描述：开放时间必须早于关闭时间
- 执行逻辑：开放时间 < 关闭时间

#### 规则15：窗口删除限制
- 规则描述：窗口下无数据关联方可删除（SRD 4.2 动态管理规则）
- 执行逻辑：窗口下无排班记录及其他关联数据

#### 规则16：窗口职能类型对应角色
- 规则描述：分配的角色编码必须与窗口职能类型对应
- 执行逻辑：
  - SIGNIN → DOCTOR_SIGNIN
  - PRECHECK → DOCTOR_PRECHECK
  - REGISTER → DOCTOR_REGISTER
  - VACCINATE → DOCTOR_VACCINATE
  - OBSERVE → DOCTOR_OBSERVE
  - STOCK → DOCTOR_STOCK
  - SCHEDULE → DOCTOR_SCHEDULE

### 5.5 业务规则

#### 规则17：疫苗编码唯一性
- 规则描述：疫苗编码必须唯一
- 执行逻辑：疫苗编码在疫苗表中不存在

#### 规则18：适龄范围有效性
- 规则描述：适龄范围最小月龄必须小于等于最大月龄
- 执行逻辑：适龄范围最小月龄 <= 适龄范围最大月龄

#### 规则19：接种剂次有效性
- 规则描述：接种剂次必须大于0
- 执行逻辑：接种剂次 > 0

#### 规则20：接种间隔有效性
- 规则描述：接种间隔必须大于0
- 执行逻辑：接种间隔 > 0

#### 规则21：疫苗删除限制
- 规则描述：疫苗下无批次记录方可删除
- 执行逻辑：疫苗下无批次记录

#### 规则22：儿童年龄适配校验
- 规则描述：儿童年龄必须在疫苗的适龄范围内
- 执行逻辑：儿童月龄 >= 适龄范围最小月龄 AND 儿童月龄 <= 适龄范围最大月龄

#### 规则23：接种间隔校验
- 规则描述：同一疫苗两次接种间隔必须符合接种间隔要求
- 执行逻辑：当前接种日期 - 上次接种日期 >= 接种间隔天数

### 6.5 业务规则

#### 规则24：公告标题必填
- 规则描述：公告标题必须填写
- 执行逻辑：公告标题不为空

#### 规则25：公告内容必填
- 规则描述：公告内容必须填写
- 执行逻辑：公告内容不为空

#### 规则26：生效时间早于失效时间
- 规则描述：生效时间必须早于失效时间
- 执行逻辑：生效时间 < 失效时间

#### 规则27：公告审批权限
- 规则描述：只有系统管理员可以审批公告
- 执行逻辑：当前用户角色为SUPER_ADMIN

#### 规则28：公告删除权限
- 规则描述：只有系统管理员可以删除公告
- 执行逻辑：当前用户角色为SUPER_ADMIN

#### 规则29：公告状态流转
- 规则描述：公告状态流转规则
- 执行逻辑：
  - PENDING → APPROVED（审批通过）
  - PENDING → REJECTED（审批拒绝）

#### 规则30：公告驳回后重新提交
- 规则描述：公告被审批拒绝后，发布人可以修改内容重新提交审批
- 执行逻辑：
  1. 发布人查看被拒绝的公告详情和审批意见
  2. 发布人修改公告内容
  3. 发布人重新提交审批，状态从 REJECTED → PENDING
- 状态流转：REJECTED → PENDING（重新提交）
- 说明：重新提交的公告视为新审批流程，审批人需重新审批

#### 规则31：公告失效机制
- 规则描述：公告失效时间到期后，系统自动标记公告为失效状态
- 执行逻辑：定时任务每分钟检查 `expire_time < NOW() AND status = 1`，满足条件时更新公告展示状态为"已失效"
- 说明：失效公告不在用户端展示，但管理端仍可查看。失效公告的数据不被删除

### 7.5 业务规则

#### 规则33：统计类型有效性
- 规则描述：统计类型必须在预定义类型列表中
- 执行逻辑：统计类型在预定义类型列表中

#### 规则34：统计日期范围有效性
- 规则描述：统计日期范围开始日期必须早于等于结束日期
- 执行逻辑：开始日期 <= 结束日期

#### 规则35：统计权限校验
- 规则描述：只有业务管理医生和系统管理员可以查看统计
- 执行逻辑：当前用户角色为DOCTOR_BUSINESS_ADMIN或SUPER_ADMIN

```

  ↓

  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-ADMIN-*）

  │   显示处理建议

  │
  ├─ 系统异常（E-ADMIN-101~104）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```
