## 1. 模块概述

### 1.1 模块定位

用户模块包含两个子模块：

1. **用户管理子模块**：负责系统用户的全生命周期管理，包括用户注册、登录、信息管理、角色分配、权限管理等，面向系统管理员和业务管理医生
2. **儿童档案子模块**：负责家长儿童档案的管理，包括档案新增、编辑、查询等，面向家长用户

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 用户注册、登录 | 疫苗预约（属于预约模块） |
| 用户信息管理 | 接种记录查询（属于接种模块） |
| 角色分配 | 公告管理（属于公告模块） |
| 权限分配 | 窗口管理（属于窗口模块） |
| 儿童档案管理 | 预检评估（属于预检模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| SUPER_ADMIN | 系统管理员 | 用户增删改查、用户冻结、角色和权限管理 |
| DOCTOR_BUSINESS_ADMIN | 业务管理医生 | 给医生分配角色、分配额外权限 |
| USER | 用户 | 注册、登录、儿童档案管理 |

### 1.4 核心业务价值

- **用户身份管理**：统一管理所有系统用户，确保身份唯一和认证安全
- **权限精细控制**：基于角色和权限的访问控制，职责明确，权限严格隔离
- **儿童档案完整**：记录儿童完整信息，支持预约接种和接种记录查询
- **系统可维护性**：支持用户冻结、解冻，保障系统安全
- **业务灵活配置**：支持动态分配角色和权限，适应业务变化

### 1.5 业务场景

**场景1：家长注册并添加儿童档案**
```
家长打开APP
  ↓
进入注册页面
  ↓
填写注册信息（手机号、验证码、密码、姓名）
  ↓
提交注册
  ↓
系统创建用户账号
  ↓
系统自动登录
  ↓
进入儿童档案页面
  ↓
点击"添加儿童"
  ↓
填写儿童信息（姓名、性别、出生日期、身份证号）
  ↓
保存儿童档案
```

**场景2：系统管理员冻结违规用户**
```
系统管理员登录管理后台
  ↓
进入用户管理页面
  ↓
查找违规用户
  ↓
查看用户详情
  ↓
点击"冻结用户"按钮
  ↓
输入冻结原因
  ↓
系统冻结用户账号
  ↓
该用户无法登录系统
```

### 2.2 功能详情

#### F-USER-001: 用户注册

**功能描述：** 新用户通过手机号注册账号，需要验证手机号。

**输入参数：**
- 手机号（必填）
- 验证码（必填）
- 密码（必填）
- 确认密码（必填）
- 姓名（必填）

**输出结果：**
- 注册成功：返回用户ID、用户信息
- 注册失败：返回失败原因

**映射API：** POST /api/user/register

**注册逻辑：**
```sql
-- 校验手机号是否已注册
SELECT COUNT(*) FROM sys_user WHERE phone = ?;
-- 结果必须为0

-- 校验验证码是否正确
SELECT COUNT(*) FROM sms_verification WHERE phone = ? AND code = ? AND is_used = 0 AND expire_time > NOW();
-- 结果必须为1

-- 创建用户
INSERT INTO sys_user (username, phone, password, real_name, status, created_at, updated_at)
VALUES (?, ?, ?, ?, 0, NOW(), NOW());

-- 标记验证码已使用
UPDATE sms_verification SET is_used = 1 WHERE phone = ? AND code = ?;
```

#### F-USER-002: 用户登录

**功能描述：** 用户通过手机号和密码登录系统。

**输入参数：**
- 手机号（必填）
- 密码（必填）

**输出结果：**
- 登录成功：返回Token、用户信息、角色列表、权限列表
- 登录失败：返回失败原因

**映射API：** POST /api/user/login

**登录逻辑：**
```sql
-- 查询用户
SELECT id, username, phone, password, real_name, status FROM sys_user WHERE phone = ?;

-- 校验密码
-- 校验用户状态（status=0才能登录）

-- 查询用户角色
SELECT r.role_code, r.role_name
FROM sys_user_role ur
JOIN sys_role r ON ur.role_id = r.id
WHERE ur.user_id = ?;

-- 查询用户权限
SELECT p.permission_code, p.permission_name
FROM sys_user_role ur
JOIN sys_role_permission rp ON ur.role_id = rp.role_id
JOIN sys_permission p ON rp.permission_id = p.id
WHERE ur.user_id = ?;
```

#### F-USER-029: 注销账户

**功能描述：** 用户可申请注销账户，注销后账户进入"已注销"状态，无法登录和使用。

**输入参数：**
- 用户确认（二次确认）

**前置条件：** 用户无进行中的预约、无未完成的接种流程

**执行逻辑：**
1. 校验用户是否有进行中的预约或接种流程
2. 如有，提示用户先完成或取消相关业务
3. 如无，弹出二次确认对话框
4. 用户确认后，将 sys_user.status 设为 2（已注销）
5. 关联的 child_profile 记录标记为"已归档"（逻辑删除，不物理删除以保留接种历史）

**映射API：** DELETE /api/user/account

**异常场景：**
- 有进行中业务（错误码2015）：提示用户先完成或取消相关业务
- 未登录（错误码2018）：账户状态异常，无法执行注销操作

### 5.1 用户注册规则

#### 规则1：手机号唯一性校验
- 规则描述：手机号作为登录账号，必须唯一
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM sys_user WHERE phone = ?;
  ```
  结果必须为0
- 失败提示返回：`该手机号已注册，请使用其他手机号`

#### 规则2：手机号格式校验
- 规则描述：手机号必须符合中国大陆手机号格式
- 执行逻辑：正则表达式校验
  ```regex
  ^1[3-9]\d{9}$
  ```
- 失败提示返回：`手机号格式不正确，请输入正确的手机号`

#### 规则3：验证码校验
- 规则描述：验证码必须正确且未过期
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM sms_verification
  WHERE phone = ? AND code = ? AND is_used = 0 AND expire_time > NOW();
  ```
  结果必须为1
- 失败提示返回：`验证码不正确或已过期，请重新获取`

#### 规则4：密码格式校验
- 规则描述：密码8-20位，必须包含大写字母、小写字母和数字
- 执行逻辑：正则表达式校验
  ```regex
  ^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,20}$
  ```
- 失败提示返回：`密码长度8-20位，必须包含大写字母、小写字母和数字`

#### 规则5：密码一致性校验
- 规则描述：密码和确认密码必须一致
- 执行逻辑：`password == confirmPassword`
- 失败提示返回：`两次输入的密码不一致，请重新输入`

#### 规则6：姓名非空校验
- 规则描述：真实姓名不能为空
- 执行逻辑：`real_name IS NOT NULL AND real_name != ''`
- 失败提示返回：`请输入真实姓名`

#### 规则7：用户名自动生成规则
- 规则描述：用户名自动生成为手机号
- 执行逻辑：`username = phone`

#### 规则8：用户初始状态规则
- 规则描述：新注册的用户初始状态为正常（status=0）
- 执行逻辑：`status = 0`

#### 规则9：验证码标记已使用规则
- 规则描述：注册成功后标记验证码已使用
- 执行逻辑：
  ```sql
  UPDATE sms_verification SET is_used = 1 WHERE phone = ? AND code = ?;
  ```

### 5.2 用户登录规则

#### 规则10：用户存在性校验
- 规则描述：登录时用户必须存在
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM sys_user WHERE phone = ?;
  ```
  结果必须为1
- 失败提示返回：`用户不存在，请先注册`

#### 规则11：密码校验
- 规则描述：登录时密码必须正确
- 执行逻辑：`input_password == stored_password`（加密后比较）
- 失败提示返回：`密码不正确，请重新输入`

#### 规则12：用户状态校验
- 规则描述：登录时校验用户状态，区分冻结和注销两种异常状态
- 执行逻辑：
  1. 若 `sys_user.status = 2`（已注销），返回错误码2019，提示：`该账户已注销`
  2. 若 `sys_user.status = 1`（已冻结），且 `sys_user.freeze_end_time IS NOT NULL AND sys_user.freeze_end_time > NOW()`（冻结期未过），返回错误码2008，提示：`该用户已被冻结，无法登录，请联系管理员`
  3. 若 `sys_user.status = 0`（正常）且冻结期已过或未冻结，校验通过

#### 规则13：登录次数限制规则
- 规则描述：同一用户连续登录失败5次，锁定账号30分钟（SRD 12.2）
- 执行逻辑：记录登录失败次数，超过5次锁定账号30分钟
- 失败提示返回：`登录失败次数过多，账号已锁定30分钟，请稍后重试`

#### 规则14：Token生成规则
- 规则描述：登录成功后生成JWT双Token，单设备登录（新登录踢出旧会话）（SRD 12.2）
- 执行逻辑：生成JWT Token
  - Access Token：有效期2小时
  - Refresh Token：有效期7天
  - 单设备登录：新登录成功后，旧会话的Token立即失效
  ```json
  {
    "userId": 1,
    "username": "user001",
    "roles": ["USER"],
    "permissions": ["appointment.book", "child.view.own", ...],
    "accessToken": "...",
    "refreshToken": "...",
    "expireTime": 1640995200000
  }
  ```

### 5.3 用户管理规则

#### 规则15：用户名唯一性校验
- 规则描述：用户名必须唯一
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM sys_user WHERE username = ? AND id != ?;
  ```
  结果必须为0
- 失败提示返回：`用户名已存在，请使用其他用户名`

#### 规则16：用户状态流转规则
- 规则描述：用户状态只能按特定顺序流转
- 允许流转：
  - 正常（0）→ 已冻结（1）
  - 正常（0）→ 已注销（2）
  - 已冻结（1）→ 正常（0）
  - 已冻结（1）→ 已注销（2）
- 禁止流转：
  - 已注销（2）→ 其他状态（终态）

#### 规则17：冻结用户规则
- 规则描述：冻结用户需要设置冻结结束时间
- 执行逻辑：`freeze_end_time IS NOT NULL AND freeze_end_time > NOW()`
- 失败提示返回：`请设置冻结结束时间`

#### 规则18：冻结用户状态更新规则
- 规则描述：冻结用户时设置freeze_end_time（null=未冻结）
- 执行逻辑：
  ```sql
  UPDATE sys_user SET freeze_end_time = ? WHERE id = ?;
  ```

#### 规则19：解冻用户规则
- 规则描述：解冻用户时将freeze_end_time设为NULL
- 执行逻辑：
  ```sql
  UPDATE sys_user SET freeze_end_time = NULL WHERE id = ?;
  ```

#### 规则20：删除用户规则
- 规则描述：只能删除已注销状态的用户
- 执行逻辑：`sys_user.status = 2`
- 失败提示返回：`只能删除已注销的用户`

#### 规则21：删除用户级联规则
- 规则描述：删除用户时级联删除相关数据
- 执行逻辑：
  ```sql
  -- 删除用户角色关联
  DELETE FROM sys_user_role WHERE user_id = ?;

  -- 删除用户额外权限关联
  DELETE FROM sys_user_permission WHERE user_id = ?;

  -- 删除儿童档案
  DELETE FROM child_profile WHERE parent_id = ?;

  -- 删除用户
  DELETE FROM sys_user WHERE id = ?;
  ```

#### 规则22：冻结机制说明
- 规则描述：系统采用双重标记实现冻结控制
- 执行逻辑：
  - `status = 1`（已冻结）：逻辑标记，用于快速判断用户是否被冻结
  - `freeze_end_time`：时间标记，记录冻结到期时间，用于自动解冻判定
  - 两者必须同时设置/清除，保持一致。冻结时 status=1 且 freeze_end_time=NOW()+7天；解冻时 status=0 且 freeze_end_time=NULL

#### 规则23：冻结解除方式
- 规则描述：冻结解除支持自动解冻和手动解冻两种方式
- 执行逻辑：
  - 自动解冻：freeze_end_time 到期后，系统定时任务自动将 status 重置为 0，freeze_end_time 重置为 NULL。系统定时任务每60秒扫描一次，将freeze_end_time <= NOW()且status=1的用户自动解冻（status重置为0，freeze_start_time置为NULL）
  - 手动解冻：SUPER_ADMIN 可通过后台管理手动解除冻结，立即将 status 重置为 0，freeze_end_time 重置为 NULL

#### 规则24：SUPER_ADMIN 账户保护规则
- 规则描述：SUPER_ADMIN 角色账户受到系统级保护，禁止对其进行冻结、注销、角色修改和权限收回操作
- 执行逻辑：
  1. SUPER_ADMIN 角色不可被修改（角色编码不可变更）
  2. SUPER_ADMIN 不可被冻结（status 不可设为 1）
  3. SUPER_ADMIN 不可被注销（status 不可设为 2）
  4. SUPER_ADMIN 的权限不可被收回
  5. 任何尝试以上操作的系统应返回错误码 2016（SUPER_ADMIN保护违规）

#### 规则25：用户注销时的级联处理规则
- 规则描述：用户注销时需进行级联处理，确保数据完整性和可追溯性
- 执行逻辑：
  1. sys_user.status 设为 2（已注销）
  2. child_profile 记录不物理删除，保留接种历史数据，标记为"已归档"
  3. 已有的预约记录保留（用于统计分析），但状态标记为"用户已注销"。预约记录status保持不变，通过关联查询sys_user.status=2识别已注销用户的预约记录
  4. 用户注销不影响已完成的接种记录的完整性和可追溯性

### 5.4 儿童档案管理规则

#### 规则26：儿童档案所有权校验
- 规则描述：用户只能访问自己的儿童档案
- 执行逻辑：`child_profile.parent_id = current_user_id`
- 失败提示返回：`无权访问该儿童档案`

#### 规则27：儿童姓名非空校验
- 规则描述：儿童姓名不能为空
- 执行逻辑：`child_profile.name IS NOT NULL AND child_profile.name != ''`
- 失败提示返回：`请输入儿童姓名`

#### 规则28：性别必填校验
- 规则描述：性别必须选择
- 执行逻辑：`child_profile.gender IN (1, 2)`
- 失败提示返回：`请选择儿童性别`

#### 规则29：出生日期必填校验
- 规则描述：出生日期必须填写
- 执行逻辑：`child_profile.birth_date IS NOT NULL`
- 失败提示返回：`请选择儿童出生日期`

#### 规则30：身份证号格式校验
- 规则描述：身份证号必须符合18位格式
- 执行逻辑：18位，符合校验规则
- 失败提示返回：`身份证号格式不正确`

#### 规则31：儿童档案数量限制规则

- 执行逻辑：

  结果必须小于等于5
- 失败提示返回：`每个用户最多添加5个儿童档案`

### 5.5 角色和权限管理规则

#### 规则32：角色分配规则
- 规则描述：系统管理员（SUPER_ADMIN）不能修改角色
- 执行逻辑：`user.role != SUPER_ADMIN`
- 失败提示返回：`不能修改系统管理员的角色`

#### 规则33：角色更新规则
- 规则描述：分配角色时先删除旧角色关联，再创建新角色关联
- 执行逻辑：
  ```sql
  -- 删除旧角色关联
  DELETE FROM sys_user_role WHERE user_id = ?;

  -- 创建新角色关联
  INSERT INTO sys_user_role (user_id, role_id) VALUES (?, ?), (?, ?), ...;
  ```

#### 规则34：权限分配规则
- 规则描述：额外权限是用户角色的补充，不影响基础角色权限
- 执行逻辑：
  ```sql
  -- 删除旧额外权限关联
  DELETE FROM sys_user_permission WHERE user_id = ?;

  -- 创建新额外权限关联
  INSERT INTO sys_user_permission (user_id, permission_id) VALUES (?, ?), (?, ?), ...;
  ```

#### 规则35：权限查询规则
- 规则描述：查询用户权限时，包含角色权限和额外权限
- 执行逻辑：
  ```sql
  -- 查询角色权限
  SELECT p.permission_code, p.permission_name
  FROM sys_user_role ur
  JOIN sys_role_permission rp ON ur.role_id = rp.role_id
  JOIN sys_permission p ON rp.permission_id = p.id
  WHERE ur.user_id = ?;

  -- 查询额外权限
  SELECT p.permission_code, p.permission_name
  FROM sys_user_permission up
  JOIN sys_permission p ON up.permission_id = p.id
  WHERE up.user_id = ?;
  ```

### 5.6 密码管理规则

#### 规则36：旧密码校验
- 规则描述：修改密码时需要验证旧密码
- 执行逻辑：`input_old_password == stored_password`
- 失败提示返回：`旧密码不正确`

#### 规则37：新密码格式校验
- 规则描述：新密码必须符合格式要求（SRD 12.2）
- 执行逻辑：正则表达式校验
  ```regex
  ^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,20}$
  ```
- 失败提示返回：`密码长度8-20位，必须包含大写字母、小写字母和数字`

#### 规则38：密码加密规则
- 规则描述：密码必须使用BCrypt加密存储（SRD 8.3）
- 执行逻辑：使用BCrypt算法加密

#### 规则39：重置密码验证码校验
- 规则描述：重置密码时需要验证短信验证码
- 执行逻辑：
  ```sql
  SELECT COUNT(*) FROM sms_verification
  WHERE phone = ? AND code = ? AND is_used = 0 AND expire_time > NOW();
  ```
  结果必须为1
- 失败提示返回：`验证码不正确或已过期`

### 5.7 状态流转规则

#### 用户状态流转

```
status=0（正常）
    ↓ 系统管理员设置freeze_end_time
freeze_end_time != NULL（冻结中）
    ↓ freeze_end_time到期 或 系统管理员解冻
freeze_end_time = NULL（正常）

status=0（正常）
    ↓ 系统管理员注销
status=2（已注销）【终态】

status=2（已注销）
    ↓ 系统管理员删除
用户被删除
```

## 8. 异常场景

### 8.1 业务异常

#### E-USER-001：手机号已注册

**场景描述：** 注册时手机号已被注册

**触发条件：**
```sql
SELECT COUNT(*) FROM sys_user WHERE phone = ?;
```
返回结果 > 0

**错误码：** 2001
**错误消息：** `该手机号已注册，请使用其他手机号`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导用户使用其他手机号
- 或引导用户登录

---

#### E-USER-002：手机号格式不正确

**场景描述：** 输入的手机号格式不正确

**触发条件：** 手机号不符合正则表达式
  ```regex
  ^1[3-9]\d{9}$
  ```

**错误码：** 2002
**错误消息：** `手机号格式不正确，请输入正确的手机号`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导用户重新输入

---

#### E-USER-003：验证码不正确

**场景描述：** 验证码不正确或已过期

**触发条件：**
```sql
SELECT COUNT(*) FROM sms_verification
WHERE phone = ? AND code = ? AND is_used = 0 AND expire_time > NOW();
```
返回结果 = 0

**错误码：** 2003
**错误消息：** `验证码不正确或已过期，请重新获取`
**HTTP状态码：** 400 Bad Request

**处理建议：**
- 显示错误消息
- 引导用户重新获取验证码

#### E-USER-004：密码格式不正确

**场景描述：** 输入的密码格式不正确

**触发条件：** 密码不符合正则表达式

**处理建议：**

- 引导用户重新输入

### 8.3 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息、请求参数、用户信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-USER-001~018）
  │   ↓
  │   返回友好错误消息给用户
  │   显示处理建议
  │   记录业务异常日志
  │
  ├─ 系统异常（E-USER-101~105）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```
