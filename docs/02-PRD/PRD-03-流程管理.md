## 1. 模块概述

### 1.1 模块定位

接种流程模块是疫苗管理系统的核心业务流程模块，负责管理从签到到留观结束的完整接种流程。该模块涵盖签到管理、预检管理、留观管理三个子模块，是连接用户端与各窗口医生操作的关键枢纽，确保接种流程的有序推进和状态流转。

### 1.2 模块边界

| 包含内容 | 不包含内容 |
|----------|------------|
| 签到验证、预约确认、窗口指引 | 疫苗目录管理（属于疫苗模块） |
| 预检评估、禁忌筛查、预检报告 | 库存分配（属于登记模块） |
| 留观监测、不良反应处理、留观结束 | 接种执行（属于接种模块） |
| 状态流转、排队管理、窗口队列 | 预约创建（属于预约模块） |

### 1.3 涉及角色

| 角色编码 | 角色名称 | 使用场景 |
|----------|----------|----------|
| USER | 家长（用户） | 查看预约进度、获取窗口指引、查看排队信息 |
| DOCTOR_SIGNIN | 签到医生 | 执行签到、确认预约、查看今日预约 |
| DOCTOR_PRECHECK | 预检医生 | 执行预检、禁忌筛查、查看待预检队列 |
| DOCTOR_OBSERVE | 留观医生 | 留观监测、不良反应处理、确认留观结束、查看留观队列 |

### 1.4 核心业务价值

- **流程标准化**：通过状态流转机制，确保接种流程按序推进，避免跳序或重复操作
- **窗口指引明确**：实时根据预约状态提供窗口指引，让家长清晰了解下一步操作
- **安全接种保障**：通过预检筛查和留观监测，确保接种安全
- **数据可追溯**：完整记录各环节操作日志，支持问题追溯和质量管控

### 1.5 流程连续性

**完整接种流程：**
```
线上预约（status=1）
    ↓
签到管理（SIGNIN模块）
    ↓ status=6
预检管理（PRECHECK模块）
    ↓ status=7
登记管理（REGISTER模块，不在此模块内）
    ↓ status=8
接种管理（VACCINATE模块，不在此模块内）
    ↓ status=10
留观管理（OBSERVE模块）
    ↓ status=2
流程完成
```

### 2.2 签到管理子模块功能详情

#### F-FLOW-001: 查询今日预约

**功能描述：** 签到医生查询当日待签到预约列表，支持筛选和搜索。

**输入参数：**
- 医生ID（从会话中获取）
- 预约日期（可选，默认当天）
- 筛选条件（可选）：ALL（全部）、ARRIVED（已到）、NOT_ARRIVED（未到）

**输出结果：**
- 预约列表：
  - 预约号
  - 儿童姓名
  - 预约日期
  - 预约时段
  - 签到状态（已到/未到）
  - 签到时间（已到时显示）
  - 操作按钮（签到，仅未到显示）

**映射API：** GET /api/signin/today?date={date}&filter={filter}

**筛选逻辑：**
- filter=ALL：返回所有当日预约（status IN (1,6,7,8,9,10)且appointment_date=指定日期）
- filter=ARRIVED：返回已签到的预约（status>=6）
- filter=NOT_ARRIVED：返回未签到的预约（status=1）

---

#### F-FLOW-002: 执行签到

**功能描述：** 签到医生核实用户身份后执行签到操作，更新预约状态并记录签到信息。

**输入参数：**
- 医生ID（从会话中获取）
- 预约ID（必填）
- 家长身份证号（必填，用于身份核实）

**输出结果：**
- 预约ID
- 预约状态（更新为status=6）
- 当前窗口（更新为当前窗口编码）
- 签到时间
- 下一步指引（指引到预检窗口）

**映射API：** POST /api/signin/signin

**业务规则：**
1. 预约状态必须为"已预约"（status=1）
2. 预约日期必须是预约当天或之前已过期但未超过系统允许的补签期限（过期预约不能签到）
3. 家长身份证号必须与儿童档案中的家长身份证号一致
4. 签到成功后更新预约状态为"已签到"（status=6）
5. 签到成功后更新当前窗口字段为签到窗口编码
6. 签到成功后记录签到时间
7. 签到成功后生成签到日志
8. 使用CAS乐观锁防止并发签到：`UPDATE appointment SET status=6 WHERE id=? AND status=1`，若affected rows=0则返回错误码3101
9. 签到时系统自动分配当前签到窗口编码到预约记录的current_window字段，家长APP通过窗口指引API获取该窗口信息

**状态流转：** status=1 → status=6

---

#### F-FLOW-003: 获取窗口指引

**功能描述：** 根据预约当前状态，获取下一步窗口指引信息。

**输入参数：**
- 预约ID（必填）
- 用户ID（从会话中获取）

**输出结果：**
- 预约ID
- 当前状态（status值）
- 当前状态描述（statusText）
- 下一步指引（nextGuide）：
  - nextAction：下一步操作名称
  - guideMessage：指引消息
  - windowCode：窗口编码
  - windowName：窗口名称
  - windowFunctionType：窗口职能类型

**映射API：** GET /api/user/appointment/{appointmentId}/guide

**指引规则：**
| 当前状态 | status值 | 下一步窗口 | 窗口职能 | 指引消息 |
|----------|----------|------------|----------|----------|
| 已预约 | 1 | 签到窗口 | SIGNIN | 您已成功预约，请到签到窗口办理签到 |
| 已签到 | 6 | 预检窗口 | PRECHECK | 签到成功，请到预检窗口等待预检 |
| 预检通过 | 7 | 登记窗口 | REGISTER | 预检通过，请到登记窗口排队 |
| 已登记 | 8 | 接种窗口 | VACCINATE | 登记完成，请到接种窗口等待接种 |
| 留观中 | 10 | 留观室 | OBSERVE | 接种完成，请在留观室观察30分钟 |

> **注：** 接种成功后（status=10），current_window 应由接种模块设为 `OBSERVE`，而非 `VACCINATE`。各模块 current_window 设置规则如下：
> - 签到完成后：current_window = 签到窗口编码
> - 预检完成后：current_window = 预检窗口编码
> - 登记完成后：current_window = 登记窗口编码
> - 接种完成后：current_window = OBSERVE
> - 留观结束后：current_window = NULL

---

#### F-FLOW-004: 获取排队信息

**功能描述：** 获取预约当前应去窗口的排队信息，包括当前排队人数、预估等待时间等。

**输入参数：**
- 预约ID（必填）
- 用户ID（从会话中获取）

**输出结果：**
- windowCode：窗口编码
- windowName：窗口名称
- windowFunctionType：窗口职能类型
- currentQueue：当前排队人数
- capacity：窗口容量
- estimatedWaitTime：预估等待时间（分钟）

**映射API：** GET /api/user/appointment/{appointmentId}/queue

**计算规则：**
- currentQueue = 统计该窗口职能下待处理的预约数（除当前预约外）
- estimatedWaitTime = currentQueue × 该窗口预估办理时间

---

#### F-FLOW-006: 执行预检评估

**功能描述：** 预检医生对儿童进行健康状况评估，记录各项指标并生成预检报告。

**输入参数：**
- 医生ID（从会话中获取）
- 预约ID（必填）
- 体温（必填，单位：℃）
- 体重（选填，单位：kg）
- 身高（选填，单位：cm）
- 健康状况（必填，健康评估描述）
- 过敏史检查（必填，0=正常/1=异常）
- 疾病史检查（必填，0=正常/1=异常）
- 近期接种检查（必填，0=正常/1=异常）
- 免疫程序检查（必填，0=正常/1=异常）

**输出结果：**
- 预检记录ID
- 预约ID
- 预检时间
- 预检结果（PASS/FAIL）
- 未通过原因（FAIL时必填）

**映射API：** POST /api/precheck/assess

**业务规则：**
1. 预约状态必须为"已签到"（status=6）
2. 体温必须填写
3. 健康状况必须填写
4. 预检评估完成后自动调用禁忌筛查
5. 预检通过后更新预约状态为"预检通过"（status=7）
6. 预检未通过后更新预约状态为"预检未通过"（status=9）

**预检结果与禁忌筛查交互规则：**
1. 预检评估 PASS + 禁忌筛查 PASS → 正常通过，进入登记环节
2. 预检评估 PASS + 禁忌筛查 FAIL → 标记为"禁忌暂缓"，不可进入登记环节。系统向用户推送通知，建议转诊至专科医院进一步评估。预约状态变更为9（预检未通过）。如已锁定库存，自动释放锁定的库存
3. 预检评估 FAIL + 禁忌筛查任意 → 标记为"预检未通过"，处理方式同上

**状态流转：** status=6 → status=7（通过）或 status=9（未通过）

---

#### F-FLOW-007: 执行禁忌筛查

**功能描述：** 根据预检评估结果，进行禁忌症筛查和风险评估。

**输入参数：**
- 预约ID（必填）
- 疫苗ID（必填）
- 过敏史检查标志（必填，0=正常/1=异常）
- 疾病史检查标志（必填，0=正常/1=异常）
- 近期接种检查标志（必填，0=正常/1=异常）
- 免疫程序检查标志（必填，0=正常/1=异常）

**输出结果：**
- 筛查结果（PASS/FAIL）
- 禁忌症类型（FAIL时返回）
- 风险等级（FAIL时返回）
- 说明（选填）

**映射API：** POST /api/precheck/contraindication

**筛查规则：**
1. 过敏史筛查：检查是否有该疫苗成分过敏史
2. 疾病史筛查：检查是否有该疫苗禁忌疾病
3. 近期接种筛查：检查近期（14天内）是否接种过其他疫苗
4. 免疫程序筛查：检查是否符合疫苗接种程序

**禁忌症类型：**
- ALLERGY：过敏史禁忌
- DISEASE：疾病史禁忌
- RECENT_VACCINATION：近期接种禁忌
- IMMUNE_SCHEDULE：免疫程序不符

---

#### F-FLOW-009: 留观状态监控

**功能描述：** 实时监控留观状态与时长，提供倒计时提醒。

**输入参数：**
- 注射号（必填）
- 医生ID（从会话中获取）

**输出结果：**
- 注射号
- 儿童姓名
- 留观开始时间
- 当前时间
- 留观时长（分钟）
- 剩余时长（分钟，倒计时）
- 留观状态（观察中/已完成）
- 标准时长（30分钟）

**映射API：** GET /api/observe/status/{injectionId}

**监控规则：**
1. 标准留观时长为30分钟
2. 留观时长从留观开始时间到当前时间计算
3. 剩余时长 = 标准时长 - 留观时长
4. 当留观时长 >= 30分钟时，可结束留观
5. 实时刷新（每秒更新倒计时）

#### F-FLOW-010: 确认留观结束

**功能描述：** 留观医生确认留观结束，完成接种流程。

**输入参数：**
- 医生ID（从会话中获取）
- 注射号（必填）
- 离开时间（必填，默认当前时间）
- 留观状态（必填，1=正常结束，2=异常结束）
- 异常描述（选填，status=2时必填）

**输出结果：**
- 预约ID
- 预约状态（更新为status=2）
- 留观结束时间
- 留观时长
- 留观状态（1=正常结束，2=异常结束）

**映射API：** POST /api/observe/finish

**业务规则：**
1. 预约状态必须为"留观中"（status=10）
2. 留观时长必须 >= 30分钟
3. 正常结束时，更新observe_record.status=1，更新预约状态为"已完成"（status=2）
4. 异常结束时，更新observe_record.status=2，记录abnormal_description，需调用不良反应上报
5. 使用CAS乐观锁防止重复确认：`UPDATE observe_record SET status=1 WHERE id=? AND status=0`，若affected rows=0则返回错误码3108
6. 留观结束后更新当前窗口为空
7. 生成留观日志
8. 留观记录创建时机：接种模块执行接种成功（status=10）时同步创建observe_record记录，初始状态为"观察中"（status=0），start_time设为接种完成时间。留观医生无需手动创建留观记录。

**状态流转：** status=10 → status=2

- 注射号（必填）

**输出结果：**

**严重程度枚举：**
- MILD：轻度
- MODERATE：中度
- SEVERE：重度

#### F-FLOW-012: 处理不良反应

**功能描述：** 留观医生处理已上报的不良反应记录。

**输入参数：**
- 医生ID（从会话中获取）
- 不良反应记录ID（必填）
- 处理措施（必填）
- 处理结果（必填）
- 处理时间（必填）
- 是否转诊（必填）
- 备注（选填）

**输出结果：**
- 不良反应记录ID
- 处理状态（更新为RESOLVED）

## 5. 业务规则

### 5.1 签到管理子模块业务规则

#### 规则1：预约状态校验（签到）
- 规则描述：预约状态必须为"已预约"（status=1）
- 执行逻辑：检查appointment.status == 1
- 失败提示返回：`该预约已签到或状态异常，无法重复签到`

#### 规则2：预约日期校验（签到）
- 规则描述：预约日期必须是当天或之前
- 执行逻辑：检查appointment.appointment_date <= 当前日期
- 失败提示返回：`该预约未到预约日期，无法签到`

#### 规则3：身份证号匹配规则（签到）
- 规则描述：输入的家长身份证号必须与儿童档案中的家长身份证号一致
- 执行逻辑：检查child_profile.parent_id_card == 输入身份证号
- 失败提示返回：`身份证号不匹配，请核对后重试`

#### 规则4：签到状态更新规则
- 规则描述：签到成功后更新预约状态为"已签到"（status=6）
- 执行逻辑：
  - 更新appointment.status = 6
  - 更新appointment.current_window = 签到窗口编码
  - 更新appointment.signin_time = 当前时间
  - 更新appointment.signin_doctor_id = 当前医生ID
  - 生成签到日志

> 注：signin_doctor_id 字段定义详见 PRD-APPOINTMENT §6 appointment 表。

#### 规则5：窗口指引规则（签到后）
- 规则描述：签到成功后，指引家长前往预检窗口
- 执行逻辑：
  - nextAction = "预检"
  - guideMessage = "签到成功，请到预检窗口等待预检"
  - windowCode = 预检窗口编码
  - windowFunctionType = "PRECHECK"

#### 规则6：队列查询规则（待预检）
- 规则描述：查询待预检的预约（已签到但未预检）
- 执行逻辑：
  - 筛选条件：appointment.status = 6 且 appointment_date = 指定日期
  - 排序：按signin_time升序排列（先签到先预检）

### 5.2 预检管理子模块业务规则

#### 规则7：预约状态校验（预检）
- 规则描述：预约状态必须为"已签到"（status=6）
- 执行逻辑：检查appointment.status == 6
- 失败提示返回：`该预约状态异常，无法进行预检`

#### 规则8：预检数据必填规则
- 规则描述：体温和健康状况必须填写
- 执行逻辑：
  - 检查temperature不为空
  - 检查health_status不为空
- 失败提示返回：`体温和健康状况为必填项`

#### 规则9：预检结果必填规则
- 规则描述：预检未通过时，未通过原因必须填写
- 执行逻辑：
  - 检查result为PASS或FAIL
  - 如果为FAIL，检查fail_reason不为空
- 失败提示返回：`预检未通过时，未通过原因为必填项`

#### 规则10：预检通过状态更新规则
- 规则描述：预检通过后更新预约状态为"预检通过"（status=7）
- 执行逻辑：
  - 保存pre_check_record记录
  - 更新appointment.status = 7
  - 更新appointment.current_window = 预检窗口编码
  - 生成预检日志

#### 规则11：预检未通过状态更新规则
- 规则描述：预检未通过后更新预约状态为"预检未通过"（status=9）
- 执行逻辑：
  - 保存pre_check_record记录
  - 更新appointment.status = 9
  - 记录未通过原因
  - 生成预检日志

#### 规则12：窗口指引规则（预检后）
- 规则描述：预检通过后，指引家长前往登记窗口
- 执行逻辑：
  - nextAction = "登记"
  - guideMessage = "预检通过，请到登记窗口排队"
  - windowCode = 登记窗口编码
  - windowFunctionType = "REGISTER"

#### 规则13：禁忌筛查规则（过敏史）
- 规则描述：检查是否有该疫苗成分过敏史
- 执行逻辑：
  - 检查allergy_history_check标志位
  - 如为1（异常），返回筛查结果FAIL，禁忌症类型ALLERGY

#### 规则14：禁忌筛查规则（疾病史）
- 规则描述：检查是否有该疫苗禁忌疾病
- 执行逻辑：
  - 检查disease_history_check标志位
  - 如为1（异常），返回筛查结果FAIL，禁忌症类型DISEASE

#### 规则15：禁忌筛查规则（近期接种）
- 规则描述：检查近期（14天内）是否接种过其他疫苗
- 执行逻辑：
  - 检查recent_vaccination_check标志位
  - 如为1（异常），返回筛查结果FAIL，禁忌症类型RECENT_VACCINATION

#### 规则16：禁忌筛查规则（免疫程序）
- 规则描述：检查是否符合疫苗接种程序
- 执行逻辑：
  - 检查immunization_check标志位
  - 如为1（异常），返回筛查结果FAIL，禁忌症类型IMMUNE_SCHEDULE

#### 规则16.5：预检未通过库存释放规则
- 规则描述：防御性规则：正常流程中预检在登记之前执行（status=6），此时未锁定库存，无需释放。本规则覆盖异常场景下可能出现的登记后回退情况——如因数据异常导致已登记的预约需要重新预检，且已锁定库存（status >= 8），则自动释放锁定的库存。
- 执行逻辑：调用库存释放接口（参考 PRD-STOCK 规则22），将锁定库存转为可用库存
- 说明：仅在预约已进入登记阶段（status >= 8）后预检回退才需释放库存；预检阶段（status=6→9）直接跳过登记，未锁定库存

### 5.3 留观管理子模块业务规则

#### 规则17：预约状态校验（留观）
- 规则描述：预约状态必须为"留观中"（status=10）
- 执行逻辑：检查appointment.status == 10
- 失败提示返回：`该预约状态异常，无法进行留观操作`

#### 规则18：留观时长校验规则
- 规则描述：留观时长必须 >= 30分钟
- 执行逻辑：
  - 计算留观时长 = 当前时间 - 留观开始时间
  - 检查留观时长 >= 30分钟
- 失败提示返回：`留观时长未达到标准（30分钟），请继续观察`

#### 规则19：留观标准时长规则
- 规则描述：标准留观时长为30分钟
- 执行逻辑：定义标准时长 = 30分钟

#### 规则20：留观时长计算规则
- 规则描述：留观时长从留观开始时间到当前时间计算
- 执行逻辑：留观时长 = 当前时间 - 留观开始时间

#### 规则21：剩余时长计算规则
- 规则描述：剩余时长 = 标准时长 - 留观时长
- 执行逻辑：剩余时长 = 30分钟 - 留观时长

#### 规则22：留观结束状态更新规则
- 规则描述：留观结束后更新预约状态为"已完成"（status=2）
- 执行逻辑：
  - 正常结束：更新observe_record.status = 1
  - 异常结束：更新observe_record.status = 2，填写abnormal_description
  - 记录留观结束时间
  - 计算留观时长（自动计算）
  - 更新appointment.status = 2
  - 更新appointment.current_window = NULL
  - 生成留观日志

#### 规则23：留观结果处理规则
- 规则描述：留观结束为异常（status=2）时，记录不良反应
- 执行逻辑：
  - 检查留观状态为0（观察中）、1（正常结束）或2（异常结束）
  - 如果为2（异常结束），必须调用不良反应上报
  - 上报成功后，方可结束留观
- 不良反应处理后留观结束规则：不良反应处理完成（处理状态RESOLVED）后，医生仍需手动确认留观结束（F-FLOW-010）。如不良反应严重且已转诊（REFERRED），可豁免30分钟留观要求，直接结束留观。不良反应上报后需同步更新vaccination_record的接种异常标记（详见PRD-VACCINATE规则16）。

#### 规则24：不良反应上报规则
- 规则描述：上报不良反应记录，记录处理状态
- 执行逻辑：
  - 保存adverse_reaction记录
  - 设置处理状态为PENDING
  - 生成不良反应上报日志

#### 规则25：不良反应处理规则
- 规则描述：处理不良反应记录，更新处理状态
- 执行逻辑：
  - 更新adverse_reaction处理信息
  - 更新处理状态为RESOLVED
  - 生成不良反应处理日志

### 5.4 状态流转规则（全流程）

#### 完整状态流转图

```
status=1（已预约）
    ↓ 用户签到（DOCTOR_SIGNIN）
status=6（已签到）
    ↓ 预检通过（DOCTOR_PRECHECK）
status=7（预检通过）
    ↓ 登记完成（DOCTOR_REGISTER，不在此模块）
status=8（已登记）
    ↓ 接种完成（DOCTOR_VACCINATE，不在此模块）
status=10（留观中）
    ↓ 留观结束（DOCTOR_OBSERVE）
status=2（已完成）

异常分支：
status=3（已取消）← 用户主动取消（USER）
status=4（已过期）← 系统自动过期（SYSTEM）
status=9（预检未通过）← 预检评估未通过（DOCTOR_PRECHECK）
```

> **预检未通过后重新预约约束：**
> 1. 预检未通过（status=9）为终态，该预约不可恢复，需重新创建预约
> 2. 重新预约不受时间限制，可立即创建新预约
> 3. 建议家长在咨询医生后重新预约，系统在预检未通过通知中附带此建议

#### 状态流转约束表

| 当前状态 | 可流转状态 | 触发条件 | 流转角色 | 子模块 |
|----------|------------|----------|----------|--------|
| 1（已预约） | 6（已签到） | 用户签到 | DOCTOR_SIGNIN | SIGNIN |
| 1（已预约） | 3（已取消） | 用户取消预约 | USER | - |
| 1（已预约） | 4（已过期） | 预约时间已过且未签到 | SYSTEM | - |
| 6（已签到） | 7（预检通过） | 预检评估通过 | DOCTOR_PRECHECK | PRECHECK |
| 6（已签到） | 9（预检未通过） | 预检评估未通过 | DOCTOR_PRECHECK | PRECHECK |
| 7（预检通过） | 8（已登记） | 登记完成 | DOCTOR_REGISTER | - |
| 8（已登记） | 10（留观中） | 接种完成 | DOCTOR_VACCINATE | - |
| 10（留观中） | 2（已完成） | 留观结束 | DOCTOR_OBSERVE | OBSERVE |

#### 状态流转校验规则总览

- 每次状态变更前，必须校验当前状态是否允许流转到目标状态
- 状态变更必须记录操作时间和操作人
- 状态变更必须生成操作日志
- 状态流转必须按序推进，不可跳序
- 异常状态（3、4、9）为终态，不可继续流转

### 5.5 CAS并发控制规则（SRD 10.4）

#### 签到CAS乐观锁
- 规则描述：使用乐观锁防止重复签到
- 执行SQL：
  ```sql
  UPDATE appointment SET status=6 WHERE id=? AND status=1
  ```
- 判断逻辑：如果affected rows = 0，说明该预约已被其他医生签到或状态已变更，返回错误码3101

#### 留观结束CAS乐观锁
- 规则描述：使用乐观锁防止重复确认留观结束
- 执行SQL：
  ```sql
  UPDATE observe_record SET status=1 WHERE id=? AND status=0
  ```
- 判断逻辑：如果affected rows = 0，说明该留观记录已被其他医生确认，返回错误码3108

### 7.4 权限校验流程

```
用户请求
  ↓
解析Token获取用户ID
  ↓
查询用户角色：sys_user_role WHERE user_id = ?
  ↓
查询角色权限：sys_role_permission WHERE role_id IN (...)
  ↓
判断请求接口是否在权限列表
  ↓
  ├─ 有权限 → 继续执行
  └─ 无权限 → 返回403 Forbidden
  ↓
数据访问权限校验
  ↓
  ├─ USER类型 → WHERE parent_id = current_user_id
  ├─ DOCTOR_SIGNIN类型 → WHERE signin_doctor_id = current_doctor_id
  ├─ DOCTOR_PRECHECK类型 → WHERE doctor_id = current_doctor_id（在pre_check_record中）
  ├─ DOCTOR_OBSERVE类型 → WHERE doctor_id = current_doctor_id（在observe_record中）
  ├─ 管理员类型 → 无限制
  └─ 其他 → 返回403 Forbidden
  ↓
执行业务逻辑
  ↓
返回响应结果
```

### 8.5 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息、请求参数、用户信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常（E-FLOW-001~015）
  │   ↓
  │   返回友好错误消息给用户
  │   显示处理建议
  │   记录业务异常日志
  │
  ├─ 系统异常（E-FLOW-101~104）
  │   ↓
  │   返回系统错误提示
  │   发送告警给运维
  │   记录系统异常日志
  │
  └─ 未知异常
      ↓
      返回通用错误提示
      发送紧急告警给运维
      记录未知异常日志
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```

### 8.6 重试机制

**可重试的异常：**
- E-FLOW-101：数据库连接异常
- E-FLOW-102：并发冲突

**重试策略：**
- 最大重试次数：3次
- 重试间隔：1秒、2秒、4秒（指数退避）
- 超时时间：30秒

**重试逻辑：**
```
重试次数 = 0
WHILE 重试次数 < 3
  尝试执行操作
  成功 → 返回结果
  失败且可重试 → 重试次数+1，等待后继续
  失败且不可重试 → 抛出异常
END WHILE
抛出异常（重试失败）
```
