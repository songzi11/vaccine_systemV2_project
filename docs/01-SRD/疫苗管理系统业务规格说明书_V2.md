## 1. 系统概述

### 1.1 系统定位

疫苗管理系统是一个部署在单家大型医院的综合性疫苗接种管理平台，支持线上预约、现场流程管理、窗口化作业、库存监控等全流程业务。

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| **单医院部署** | 系统仅支持单家医院，聚焦于大型医院内部精细化管理 |
| **窗口化作业** | 医院内设多个职能窗口，每个窗口分配特定角色的医生 |
| **流程化作业** | 从签到到留观结束，整个流程分为6个环节，按顺序推进 |
| **权限细粒度** | 10种角色，48个权限，职责明确，权限严格隔离 |
| **实时指引** | 系统根据预约状态，自动指引家长前往下一个窗口 |
| **FEFO管理** | 疫苗批次采用先过期先出原则，优先使用临期库存 |
| **窗口灵活配置** | 窗口数量、职能、容量均可动态调整，不硬编码 |
| **业务管理集中** | 业务管理医生负责医生权限分配和窗口配置维护 |

### 4.2 窗口配置（动态可维护）

**窗口配置表字段:**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | bigint | 主键 |
| window_code | varchar(50) | 窗口编码（唯一，如SIGNIN01） |
| window_name | varchar(100) | 窗口名称 |
| window_desc | varchar(500) | 窗口描述 |
| window_function_type | varchar(50) | 窗口职能类型（SIGNIN/PRECHECK等） |
| assigned_role_code | varchar(50) | 分配的角色编码（如DOCTOR_PRECHECK） |
| capacity | int | 同时接待人数 |
| open_time | time | 开放时间 |
| close_time | time | 关闭时间 |
| status | tinyint | 状态（0=开放，1=关闭） |
| sort_order | int | 排序 |

**窗口可动态维护:**
- ✅ 新增窗口：业务管理医生可随时添加新窗口
- ✅ 修改窗口：可调整窗口名称、职能、容量等
- ✅ 删除窗口：无数据关联的窗口可删除
- ✅ 调整职能：可修改窗口的职能类型（但需谨慎）
- ✅ 调整容量：可根据实际情况调整窗口容量

**示例窗口配置:**
```
窗口编码: SIGNIN01
窗口名称: 签到窗口1
职能类型: SIGNIN
分配角色: DOCTOR_SIGNIN
容量: 5人
开放时间: 08:00
关闭时间: 17:00
状态: 开放

窗口编码: PRECHECK01
窗口名称: 预检窗口1
职能类型: PRECHECK
分配角色: DOCTOR_PRECHECK
容量: 3人
开放时间: 08:00
关闭时间: 17:00
状态: 开放
```

| service_detail | text | 业务详情说明（用户可见） |
| estimated_time | int | 预估办理时间（分钟） |
| tips | varchar(500) | 温馨提示（用户可见） |
| require_items | varchar(200) | 需携带物品（用户可见） |

**示例服务说明:**
```
窗口: SIGNIN01
业务名称: 签到服务
业务描述: 身份核实与预约确认
业务详情: 请出示家长身份证和儿童接种卡，工作人员将核实您的预约信息
预估时间: 5分钟
温馨提示: 请携带儿童和本人身份证原件
需携带物品: 身份证、儿童接种卡、预约短信

窗口: PRECHECK01
业务名称: 预检服务
业务描述: 健康状况评估与禁忌筛查
业务详情: 医生将询问儿童近期健康状况、过敏史、用药情况等信息
预估时间: 10分钟
温馨提示: 请如实告知儿童健康状况和过敏史
需携带物品: 儿童接种卡
```

### 4.4 窗口排队统计

**排队统计视图字段:**
| 字段名 | 说明 |
|--------|------|
| window_code | 窗口编码 |
| window_name | 窗口名称 |
| window_function_type | 职能类型 |
| max_capacity | 最大容量 |
| current_queue_count | 当前排队人数 |
| completed_count | 今日已完成人数 |
| open_status | 窗口开放状态（开放中/已关闭/未开放） |
| busy_status | 窗口忙闲状态（空闲/繁忙） |
| estimated_wait_time | 预估等待时间（分钟） |

**排队统计逻辑:**
```
当前排队人数 = 统计当前在该窗口职能下待处理的预约数
今日已完成人数 = 统计今日该窗口职能下已完成的预约数
窗口开放状态 = 根据当前时间和窗口开放/关闭时间判断
窗口忙闲状态 = 当前排队人数 >= 最大容量 则为繁忙
预估等待时间 = 当前排队人数 × 该窗口预估办理时间
```

### 4.5 排队叫号规则

#### 排队策略

| 规则 | 说明 |
|------|------|
| 排队方式 | 按登记时间 FIFO（先进先出） |
| 排队号格式 | 窗口职能前缀 + 3位序号，如 A001（登记）、V001（接种） |
| 排队范围 | 按窗口职能类型分别排队，不同职能窗口独立队列 |

#### 叫号机制

| 步骤 | 说明 |
|------|------|
| 叫号触发 | 医生在终端点击"叫下一位" |
| 通知方式 | APP推送叫号通知（显示窗口号和排队号） |
| 就位确认 | 家长到窗口后，医生在终端点击"确认到号" |
| 超时处理 | 叫号后 5 分钟未确认，系统自动过号 |

#### 过号处理

| 规则 | 说明 |
|------|------|
| 首次过号 | 排到当前队列末尾，APP推送过号提醒 |
| 二次过号 | 排到当前队列末尾，APP推送二次提醒 |
| 三次过号 | 自动取消排队，状态回退到"已登记待分配"，需到登记窗口重新取号 |

#### 时段容量管理

| 配置项 | 说明 |
|--------|------|
| 时段粒度 | 30分钟一个时段（如 08:00-08:30、08:30-09:00） |
| 时段容量 | 每时段最大接待人数，由窗口配置中的 capacity 决定 |
| 满员策略 | 当时段已满时，预约页面该时段显示"已满"，不可选择 |
| 容量调整 | 业务管理医生可在窗口配置中动态调整容量

### 4.6 窗口指引规则

**预约状态 → 窗口指引映射:**
| 预约状态 | status值 | 应去窗口 | 指引消息 |
|----------|----------|----------|----------|
| 已预约 | 1 | 签到窗口 | 您已成功预约，请到签到窗口办理签到 |
| 已签到 | 6 | 预检窗口 | 签到成功，请到预检窗口等待预检 |
| 预检通过 | 7 | 登记窗口 | 预检通过，请到登记窗口排队 |
| 已登记 | 8 | 接种窗口 | 登记完成，请到接种窗口等待接种 |
| 留观中 | 10 | 留观室 | 接种完成，请在留观室观察30分钟 |
| 已完成 | 2 | 无 | 接种流程已完成，感谢您的配合 |
| 已取消 | 3 | 无 | 该预约已取消 |
| 已过期 | 4 | 无 | 该预约已过期，请重新预约 |
| 预检未通过 | 9 | 无 | 预检未通过，请咨询医生后重新预约 |

## 5. 核心业务流程

### 5.1 完整业务流程图

### 5.2 业务流程节点详解

#### 节点1：线上预约

**操作者：** 用户（家长）
**操作位置：** 手机APP
**操作步骤：**
1. 家长登录系统
2. 进入疫苗预约页面
3. 查看疫苗目录
4. 选择要接种的疫苗
5. 查看可用日期和时段
6. 选择预约日期和时段
7. 选择儿童档案
8. 提交预约

**系统处理：**
1. 检查用户预约权限（是否被冻结）
2. 检查儿童档案是否完善
3. 检查疫苗是否上架
4. 检查预约时间是否有效
5. 检查该时段是否满员
6. 生成预约记录
7. 发送预约成功通知（短信/APP推送）

**输出结果：**
- 预约成功：返回预约ID、预约详情
- 预约失败：返回失败原因

---

#### 节点1.5：儿童档案管理

**操作者：** 用户（家长）
**操作位置：** 手机APP

**添加儿童档案：**
1. 家长进入"我的儿童"页面
2. 点击"添加儿童"
3. 填写儿童信息：姓名（必填）、出生日期（必填）、性别、身份证号、过敏史、疾病史
4. 提交保存

**系统校验：**
1. 手机号格式校验
2. 同一家长下，儿童姓名 + 出生日期不可重复
3. 出生日期不可晚于当前日期
4. 身份证号格式校验（如填写），且不可与已有档案重复

**编辑儿童档案：**
1. 家长选择要修改的儿童
2. 修改可编辑字段（姓名、过敏史、疾病史等）
3. 出生日期和身份证号不可修改（如需修改，联系管理员）
4. 提交保存

---

#### 节点2：签到

**操作者：** 签到医生
**操作位置：** 签到窗口
**操作步骤：**
1. 家长到签到窗口
2. 出示家长身份证和儿童接种卡
3. 签到医生扫码或输入预约号
4. 系统显示预约详情
5. 医生核实身份信息
6. 医生确认预约
7. 系统分配预检窗口

**系统处理：**
1. 查询预约记录
2. 检查预约状态（是否已签到/已取消/已过期）
3. 验证预约时间有效性
4. 更新预约状态：status=6（已签到）
5. 更新当前窗口：current_window='SIGNIN'
6. 记录签到时间
7. 生成签到日志

**输出结果：**
- 签到成功：系统指引"请到预检窗口等待"
- 签到失败：返回失败原因

---

#### 节点3：预检

**操作者：** 预检医生
**操作位置：** 预检窗口
**操作步骤：**
1. 家长到预检窗口
2. 预检医生扫码或输入预约号
3. 询问儿童健康状况（体温、体重、身高）
4. 询问用药情况
5. 检查过敏史
6. 检查近期接种史
7. 检查疾病史
8. 执行禁忌筛查（过敏史、疾病史、近期接种、免疫程序）
9. 生成预检评估结果（PASS/FAIL）

**系统处理：**
1. 查询预约记录
2. 检查预约状态（是否已完成预检）
3. 保存预检记录
4. 更新预约状态：
   - 预检通过：status=7（预检通过）
   - 预检未通过：status=9（预检未通过）
5. 更新当前窗口：current_window='PRECHECK'
6. 生成预检报告

**输出结果：**
- 预检通过：系统指引"请到登记窗口排队"
- 预检未通过：系统提示"预检未通过，请咨询医生后重新预约"

---

#### 节点4：登记

**操作者：** 登记医生
**操作位置：** 登记窗口
**操作步骤：**
1. 家长到登记窗口
2. 登记医生扫码或输入预约号
3. 核实儿童信息
4. 确认预约信息
5. FEFO分配疫苗批次（优先使用快过期的）
6. 锁定库存
7. 生成排队号（A001, A002...）
8. 通知家长排队号

**系统处理：**
1. 查询预约记录
2. 检查预约状态（是否已预检通过）
3. FEFO查询可用批次：
   ```sql
   SELECT * FROM vaccine_batch
   WHERE vaccine_id = ? AND expiry_date > NOW() AND status = 0
   ORDER BY expiry_date ASC LIMIT 1
   ```
4. 锁定批次库存：
   - available_stock不变
   - locked_stock += 1
5. 更新预约状态：status=8（已登记）
6. 更新当前窗口：current_window='REGISTER'
7. 保存登记排队记录
8. 生成登记日志

**输出结果：**
- 登记成功：返回排队号、批次信息，系统指引"请到接种窗口等待"
- 登记失败（无可用批次）：该疫苗所有批次库存不足或已过期，返回错误提示，建议家长改期接种

---

#### 节点5：接种

**操作者：** 接种医生
**操作位置：** 接种窗口
**操作步骤：**
1. 家长到接种窗口
2. 接种医生扫码或输入排队号
3. 核实儿童信息
4. 选择接种部位（左上臂/右臂/左臀部/右臀部）
5. 执行疫苗接种
6. 生成注射号（唯一）
7. 扣减库存
8. 记录接种信息
9. 通知家长开始留观

**系统处理：**
1. 查询预约记录
2. 检查预约状态（是否已登记）
3. 检查批次库存是否足够
4. 生成唯一注射号
5. 扣减库存：
   - available_stock -= 1
   - locked_stock -= 1
6. 更新预约状态：status=10（留观中）
7. 更新当前窗口：current_window='VACCINATE'
8. 保存接种记录
9. 生成接种日志

**输出结果：**
- 接种成功：返回注射号、接种部位
- 系统指引"请在留观室观察30分钟"

---

#### 节点6：留观

**操作者：** 留观医生
**操作位置：** 留观室
**操作步骤：**
1. 家长带孩子进入留观室
2. 留观医生扫码或输入注射号
3. 开始留观计时
4. 监测儿童状态（30分钟）
5. 如出现不良反应，记录并处理
6. 留观结束，确认无异常
7. 更新留观记录
8. 结束流程

**系统处理：**
1. 查询预约记录
2. 检查预约状态（是否已接种）
3. 保存留观开始时间
4. 保存留观结束时间
5. 计算留观时长
6. 判断是否达到标准（≥30分钟）
7. 更新预约状态：status=2（已完成）
8. 更新当前窗口：current_window=null
9. 生成留观日志
10. 发送接种完成通知

**输出结果：**
- 留观结束：系统提示"接种流程已完成，感谢您的配合"
- 有不良反应：系统通知医生处理

---

### 5.3 异常流程处理

#### 取消预约

**触发条件：**
- 家长主动取消
- 预约过期自动取消

**处理流程：**
1. 检查预约状态（已完成不可取消）
2. 更新预约状态：status=3（已取消）
3. 释放锁定的库存（如有）
4. 记录取消原因
5. 发送取消通知

**爽约惩罚：**
- 记录爽约次数
- 爽约3次，冻结预约权限7天
- 冻结期间无法预约

---

#### 预检未通过

**触发条件：**
- 儿童发热
- 有严重过敏史
- 近期接种过其他疫苗
- 有疾病禁忌

**处理流程：**
1. 更新预约状态：status=9（预检未通过）
2. 记录未通过原因
3. 系统提示"请咨询医生后重新预约"

---

### 5.4 通知机制

#### 通知触发规则

| 触发事件 | 通知渠道 | 通知对象 | 通知内容 |
|----------|----------|----------|----------|
| 预约成功 | APP推送 + 短信 | 家长 | 预约成功确认信息（疫苗名称、日期、时段） |
| 预约取消 | APP推送 | 家长 | 取消确认及原因 |
| 签到完成 | APP推送 | 家长 | 下一步窗口指引（预检窗口信息、排队情况） |
| 预检通过 | APP推送 | 家长 | 下一步窗口指引（登记窗口信息、排队情况） |
| 登记完成 | APP推送 | 家长 | 排队号、前方等待人数、接种窗口信息 |
| 接种完成 | APP推送 + 短信 | 家长 | 留观提醒（留观位置、30分钟计时开始） |
| 留观结束 | APP推送 + 短信 | 家长 | 接种流程完成确认 |
| 叫号提醒 | APP推送 | 家长 | 当前叫号信息（窗口号、排队号） |
| 过号提醒 | APP推送 | 家长 | 过号提醒及重新排队信息 |
| 库存预警 | 系统消息 | 库存医生 | 低库存/临期/过期预警详情 |
| 不良反应 | 系统消息 | 相关医生 | 不良反应上报通知 |

#### 通知渠道优先级

```
APP推送（主渠道） → 短信（备用渠道，APP推送失败或紧急通知时使用）
```

#### 通知发送策略

| 策略 | 说明 |
|------|------|
| 发送方式 | 异步发送，不阻塞业务流程 |
| 失败重试 | 最多重试3次，间隔1分钟 |
| 去重机制 | 同一事件5分钟内不重复发送相同通知 |
| 模板管理 | 通知模板存储在数据库，支持运营人员修改 |

#### 爽约判定标准

| 规则 | 说明 |
|------|------|
| 爽约判定 | 预约时段结束后 30 分钟未签到，系统自动标记为爽约 |
| 时段结束时间 | 以各窗口配置的 close_time 为准 |
| 爽约处理 | 自动更新预约状态为"已过期"（status=4），累加爽约次数 |
| 冻结机制 | 累计爽约3次，冻结预约权限7天，冻结期间无法提交新预约 |
| 冻结解除 | 7天后自动解除，或由系统管理员手动解除 |

## 6. 流程参考

> 本章为第5章"核心业务流程"的快速参考，包含状态流转图、权限速查和数据完整性清单。各环节的详细操作步骤和系统处理逻辑请参见第5章。

### 6.1 预约状态流转

```
status=1（已预约）
    ↓ 用户签到
status=6（已签到）
    ↓ 进入预检窗口
status=7（预检通过）
    ↓ 进入登记窗口
status=8（已登记）
    ↓ 进入接种窗口
status=10（留观中）
    ↓ 留观结束
status=2（已完成）

异常分支：
status=3（已取消）
status=4（已过期）
status=9（预检未通过）
```

### 6.2 各环节权限要求

| 环节 | 窗口 | 角色 | 权限 | 可操作数据 |
|------|------|------|------|-----------|
| 签到 | SIGNIN | DOCTOR_SIGNIN | appointment.signin, appointment.confirm | 预约记录 |
| 预检 | PRECHECK | DOCTOR_PRECHECK | precheck.assess, precheck.contraindication | 预约、预检记录 |
| 登记 | REGISTER | DOCTOR_REGISTER | register.verify, register.batch.assign | 预约、库存 |
| 接种 | VACCINATE | DOCTOR_VACCINATE | vaccinate.execute, vaccinate.record | 预约、接种记录、库存 |
| 留观 | OBSERVE | DOCTOR_OBSERVE | observe.manage, observe.finish | 预约、留观记录、不良反应 |

### 6.3 数据完整性要求

| 数据项 | 必填时机 | 验证规则 |

### 7.2 FEFO（First Expired First Out）批次分配

**规则：** 优先使用有效期最早的批次

**分配SQL：**
```sql
SELECT b.*, s.available_stock
FROM vaccine_batch b
JOIN hospital_vaccine_stock s ON b.id = s.batch_id
WHERE b.vaccine_id = ?
  AND s.hospital_id = ?
  AND b.status = 0  -- 正常状态
  AND s.available_stock > 0
  AND b.expiry_date > NOW()
ORDER BY b.expiry_date ASC
LIMIT 1
FOR UPDATE;  -- 加锁防止并发
```

**分配流程：**
1. 查询符合条件的批次（按有效期升序）
2. 选取第一个可用批次
3. 返回批次信息

### 7.3 库存扣减流程

**登记时（预约锁定）：**
```sql
-- 锁定库存（不减可用库存）
UPDATE hospital_vaccine_stock
SET locked_stock = locked_stock + 1
WHERE batch_id = ? AND available_stock > 0;
```

**接种时（实际扣减）：**
```sql
-- 扣减库存
UPDATE hospital_vaccine_stock
SET available_stock = available_stock - 1,
    locked_stock = locked_stock - 1
WHERE batch_id = ? AND available_stock > 0;
```

**取消预约时（释放锁定）：**
```sql
-- 释放锁定
UPDATE hospital_vaccine_stock
SET locked_stock = locked_stock - 1
WHERE batch_id = ? AND locked_stock > 0;
```

### 7.4 库存预警机制

**预警类型：**

1. **低库存预警** (LOW_STOCK)
   - 触发条件：`remaining_ratio < 20%`
   - 剩余率计算：`(available_stock / (available_stock + locked_stock)) * 100`
   - 处理动作：自动调用供应商接口补货

2. **临期预警** (EXPIRY_SOON)
   - 触发条件：`expiry_date - warning_days < NOW()`
   - 标记批次：`status = 1`（临期）
   - 处理动作：推送临期通知给库存医生

3. **过期预警** (EXPIRED)
   - 触发条件：`expiry_date < NOW()`
   - 标记批次：`status = 2`（过期）
   - 处理动作：不可继续使用，需销毁

**预警日志表 (stock_alert_log):**
| 字段名 | 说明 |
|--------|------|
| alert_type | LOW_STOCK / EXPIRY_SOON / EXPIRED |
| vaccine_id | 疫苗ID |
| batch_no | 批次号 |
| remaining_ratio | 剩余率（%） |
| expiry_date | 有效期至 |
| synced_to_supplier | 是否已同步供应商（0=否，1=是） |

### 7.5 库存调拨

**说明：** 系统仅支持单医院部署，库存调拨主要在医院内部不同位置之间进行

**调拨流程：**
1. 库存医生发起调拨申请
2. 系统检查源位置库存是否充足
3. 系统扣减源位置库存
4. 系统增加目标位置库存
5. 记录调拨日志

**调拨日志表 (stock_transfer_log):**
| 字段名 | 说明 |
|--------|------|
| batch_id | 批次ID |
| from_type | 0=总仓，1=接种点 |
| from_id | 调出位置ID |
| to_type | 0=总仓，1=接种点 |
| to_id | 调入位置ID |
| quantity | 调拨数量 |
| operator_id | 操作员ID |

## 10. 异常处理规则

### 10.1 异常分类

**HTTP 状态码规范：**

| 异常类型 | 错误码 | 说明 |
|----------|--------|------|
| 401 | UNAUTHORIZED | 未认证或Token无效 |
| 403 | FORBIDDEN | 无权限访问 |
| 400 | BAD_REQUEST | 请求参数错误 |
| 404 | NOT_FOUND | 资源不存在 |
| 409 | CONFLICT | 数据冲突（如重复预约） |
| 500 | INTERNAL_ERROR | 系统内部错误 |

**业务错误码规范：**

各模块的业务错误码由对应模块 PRD 独立定义，采用模块前缀分段编码，各模块码段不重叠：

| 模块 | 业务异常 | 系统异常 | 对应 PRD |
|------|---------|---------|----------|
| 系统级 | 1000-1499 | 1500-1999 | 认证、权限、参数等通用错误 |
| 用户模块 | 2001-2050 | 2051-2099 | PRD-USER |
| 预约模块 | 3001-3050 | 3051-3099 | PRD-APPOINTMENT |
| 流程模块 | 3101-3150 | 3151-3199 | PRD-FLOW |
| 接种模块 | 3201-3250 | 3251-3299 | PRD-VACCINATE |
| 库存模块 | 4001-4050 | 4051-4099 | PRD-STOCK |
| 登记模块 | 4101-4150 | 4151-4199 | PRD-REGISTER |
| 管理模块 | 5001-5050 | 5051-5099 | PRD-ADMIN |

> **说明：** 各模块业务异常用于输入校验、业务规则违反等场景；系统异常用于数据库异常、并发冲突、服务不可用、权限不足等场景。具体错误码定义、触发条件和错误消息详见各模块 PRD 的"异常场景"章节。

### 10.2 异常处理流程

```
异常发生
  ↓
记录错误日志（含堆栈信息）
  ↓
判断异常类型
  ↓
  ├─ 业务异常 → 返回友好提示给用户
  └─ 系统异常 → 返回系统错误提示 + 发送告警给管理员
  ↓
事务回滚（如有）
  ↓
返回统一响应格式
```

### 10.3 事务处理规则

**需要事务的场景：**
1. 预约提交（需检查库存、排班容量）
2. 登记分配批次（需锁定库存）
3. 接种执行（需扣减库存）
4. 留观结束（需更新多个状态）
5. 权限分配（需级联更新）

**事务隔离级别：** READ_COMMITTED

**超时设置：** 30秒

### 10.4 并发控制策略

#### 各环节并发控制

| 环节 | 并发风险 | 控制方式 | 说明 |
|------|----------|----------|------|
| 签到 | 同一预约被多个签到窗口同时扫码 | 乐观锁（CAS） | UPDATE appointment SET status=6 WHERE id=? AND status=1，影响行数为0则表示已被处理 |
| 登记 | 多个登记窗口同时锁定同一批次 | 数据库行锁 | FEFO查询使用 `SELECT ... FOR UPDATE`，锁定选中批次行 |
| 接种 | 多个接种窗口同时扣减同一批次库存 | 数据库行锁 + 条件校验 | UPDATE ... WHERE available_stock > 0，配合 FOR UPDATE 防超卖 |
| 留观结束 | 重复确认留观结束 | 乐观锁（CAS） | UPDATE observe_record SET status=1 WHERE id=? AND status=0 |
| 库存调拨 | 并发调拨导致库存为负 | 乐观锁 | hospital_vaccine_summary 表使用 version 字段做乐观锁校验 |

#### 重试策略

```
乐观锁/行锁冲突时的重试策略：
1. 捕获冲突异常（影响行数为0 / 死锁异常）
2. 等待 100ms（固定间隔）
3. 重新执行业务操作
4. 最多重试 3 次
5. 3 次仍失败，返回业务错误提示（错误码见各模块PRD）
```

#### 隔离级别说明

本系统采用 `READ_COMMITTED` 隔离级别，配合以下措施避免并发问题：
- **库存场景：** 关键查询使用 `FOR UPDATE` 显式加行锁，在 READ_COMMITTED 下即可防止脏读和不可重复读
- **状态流转场景：** 使用 CAS（Compare-And-Swap）模式更新状态，通过 WHERE 条件保证原子性
- **不使用 REPEATABLE_READ 的原因：** READ_COMMITTED + FOR UPDATE 已满足业务需求，且锁范围更小，并发性能更优

## 附录C：部署建议

### C.1 数据库部署

**数据库版本：** MySQL 8.0+

**初始化步骤：**
1. 创建数据库：vaccine_systemv3
2. 执行角色重构脚本：migration_role_refactor_v3.sql
3. 执行窗口指引脚本：migration_window_guide.sql
4. 验证表结构：检查所有表是否创建成功
5. 导入初始数据：角色、权限、窗口配置

### C.2 应用部署

**环境要求：**
- JDK 11+
- Spring Boot 2.7+
- MySQL 8.0+
- Redis（缓存，可选）

**配置项：**
- 数据库连接
- JWT密钥
- 文件上传路径
- 外部接口地址（供应商接口）

### C.3 监控建议

**监控指标：**
- API响应时间
- 数据库连接池状态
- 队列长度（各窗口排队数）
- 库存预警
- 异常数量

**告警阈值：**
- API响应时间 > 2秒（与12.1性能需求对齐）
- 数据库连接池使用率 > 80%
- 库存低于阈值
- 异常数量突增
